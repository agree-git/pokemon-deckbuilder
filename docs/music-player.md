# Esc 음악 플레이어

main `bd11aae`: 전투·야영지 Esc 메뉴에 음악 플레이어를 추가했다. 버전/EXE/export/Windows CI/Release는 사용자의 재요청까지 보류한다.

## 최소 파일 지도

- `scripts/audio/game_music.gd`: `next_track`, `previous_track`, `toggle_playback`, `current_track_title`. `can_next_track`/`can_previous_track`와 `theme_changed`/`playback_changed`가 UI 상태를 연결한다.
- `scripts/ui/music_player_panel.gd`: 양쪽 메뉴의 공용600×360 플레이어. 곡 제목/전체 제목 툴팁, 음표 커버, 현재 시간/길이/진행 표시, 이전/재생·일시정지/다음, 음악 음량/백분율. 진행바는 표시용이며 탐색 기능은 없다.
- `scripts/ui/tactical_ui.gd::_build_menu`:1320×920 두 열. 왼쪽 플레이어/스크롤 유물, 오른쪽 가방/소진 카드/설정/화면 이동. 버튼24px간격과패널40px여백을 유지한다.
- `scripts/ui/tactical_journey_ui.gd::_open_pause_menu`: 야영·비전투 Esc는 시작 화면으로 즉시 이동하는 대신1320×520 메뉴를 연다. 플레이어/계속하기/설정/시작 화면. 기존 덱·교체·준비 등 팝업의 Esc 우선순위는 유지하며 하단 안내도 갱신했다.

## 동작 계약

- 일반 전투·야영지는 공급된35곡 중 현재 곡을 제외하고 무작위 선택한다. 기존 두 음성/1.2초 교차 페이드를 그대로 사용한다. 연속 조작도 같은 페이드 처리다.
- 지역별 `region_history`/커서를 앱 세션 안에 보관한다. 이전 곡은 실제 이력으로 복귀하며 다음 곡은 앞선 이력이 있으면 재생하고 끝에서 새 곡을 고른다. 교체된 곡을 `region_choices`에 반영해 UI 새로고침/전투·야영 전환에 되돌리지 않는다. 새 지역 선택의 연속 중복 금지도 유지한다. 새 원정이면 이력을 초기화한다.
- 선택은 기존 `_selection_rng`만 사용한다. 게임의전역/원정/전투 RNG·UID·snapshot·저장 파일에는 음악 이력/일시정지를 넣지 않는다. 앱을 종료한 뒤 음악 위치/이력의 복구는 지원하지 않는다.
- 관장/사천왕/챔피언의 전용 곡은 이전/다음이 비활성화되며 툴팁으로 안내한다. 재생·일시정지와 음악 음량은 전용곡에서도 사용할 수 있다. 원정 음악으로 돌아오면 이력을 다시 쓴다.
- `playback_paused`는 음악만 멈춘다. 음소거 해제/음량 변경이 사용자 일시정지를 풀지 않으며 멈춘 채 곡을 바꿔도 새 곡은 멈춰 있다. 음량은 Preferences의 기존 음악 음량과 같은 값/저장 경로를 쓴다.
- 메뉴의 기존 저역통과 필터와 중첩 설정창 등록은 유지한다. 음악 일시정지는 환경음/효과음에 영향을 주지 않는다. 곡 끝에서는 기존처럼 반복하며 자동으로 다음 곡에 넘어가지는 않는다.

## 이번 검증과 재실행 진입점

Godot4.7.2 실제 X11/1920×1080/Dummy 믹서와 격리된 XDG 경로로 확인했다. 전체 기술/원정/애니메이션 검사를 반복하지 않았다.

`tests/native_music_player.gd`를 `tools/native_pointer.py`로 실행한다. 일반 실행은 음악/실제 Esc·버튼·슬라이더/전용곡/페이드/저장 보존을 한 묶음45항목으로 검사한다. `MUSIC_PLAYER_CHECK=camp-popup`은 실제 덱 버튼→Esc 닫기→다시 Esc 음악 메뉴→계속하기·저장 보존7항목만 실행한다.

- 최초 실행45항목 중3개 실패:2개는 메뉴 닫힘 애니메이션 전 판정,1개는 덱을 열면서 상태 설정을 우회한 잘못된 fixture 호출이었다. 게임 오류로 확인된 것은 없다.
- 입력 대기 뒤2프레임을 기다리도록 보정한 동일 묶음에서44개 통과/잘못된 덱 fixture1개 실패. 실제 다음·이전·재생·일시정지·음량10회 OS클릭, 페이드/먹먹함/중첩 설정/일반·전용곡·실제 저장 보존은 이 실행에서 통과했다.
- 덱 호출을 실제 `deck_button` OS클릭으로 수정한 뒤 **그 구간만 재실행7검사/0실패·1 OS클릭**. 추가한 야영지 하단 안내도 이 실행으로 로드했다. 수정한 전체45항목은 다시 돌리지 않았다.
- PNG4장 중 전투·전용곡·야영지3장 시각 확인. `/tmp/pokemon-music-player/`, 정상 최종 범위 로그 `/tmp/pokemon-music-player-focused.log`; 앞선 묶음 로그는 `/tmp/pokemon-music-player-recheck.log`. 최종 범위에는 SCRIPT ERROR/ERROR/누수가 없고 기존 소프트웨어 VSync 안내만 있다.
- 실제 원정 snapshot/UID·RNG/저장 바이트와 야영 fixture snapshot 불변. 음악 재생부는 기존 음원과 믹서를 사용하며 이번 창 검사는 Dummy 출력이라 사람의 실제 스피커 청음 검사는 하지 않았다. 새 버전/EXE/패키지 검사는 하지 않았다.

다음에는 실제 플레이 피드백을 우선한다. 음악을 바꿀 때만 이 파일과 공용 플레이어/오디오 API를 읽고, 관련 수정이 없으면 기존 전체 soundscape/UI 묶음을 반복하지 않는다.
