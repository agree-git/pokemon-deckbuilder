# 원정 v28 도전 난도와 Windows 배포

사용자는 평균적으로 클리어가 어렵기를 원하며, 부족하면 조정한 EXE를 요청했다. 이 요청으로 난도 조정·EXE/export를 재개했다. 기존 v27 이하 원정은 이전 난도를 유지하고 새 원정부터 v28이다. 효과 버전19·승인 파티·대표·기술·경로/RNG·경험치·레벨·보상 가격은 유지한다.

## 변경 지도

- `data/campaign_challenge_v28.json`: 지역/상대 역할별 직접 공격 배율과 개시 보호막,휴식률. 출시 후 수정하지 않고 후속 버전을 만든다.
- `scripts/tactics/campaign_challenge.gd`: 상대 정의에3개 난도 메타데이터를 붙이고 최종 예고 피해에1번만 적용. 고정 피해/비공격 행동은 제외. 연타는 매 타격을 올림한 뒤 총합을 갱신한다.
- `campaign_route.gd`,`tactical_journey.gd`: 새 원정/희귀 조우에만 메타데이터를 연결. 휴식은40→35→30%이며 기존50%는 보존한다.
- `tactical_battle.gd`: 각 상대의 첫 보호막과 최종 행동 예고/실제 피해 연결. 첫 상대 행동 직전 기존 규칙대로 보호막이 사라진다.
- `enemy_tactics.gd`,`main_menu.gd`,`tactical_journey_ui.gd`: 압박/보호막 고지와 시작 안내,실제 회복률 표시.
- `journey_save.gd`,`journey_snapshot.gd`: v27 실제 지문 허용/새 JSON 지문 포함,전투 seed-원정 seed로 해당 전투 노드를 찾아 난도 필드 변조 거부. 기존 저장에 새 필드 주입도 거부한다.

상대 개시 보호막은 트레이너12%/베테랑18%/관장30%/사천왕35%/챔피언40%의 각 최대 HP다. 야생은0%. 직접 공격 배율은 첫 지역 야생100%에서 후반135%,트레이너110→155%,베테랑115→170%,관장125→195%,사천왕200%,챔피언210%다. 첫 지역 야생은 이전 공격 압박을 유지한다.

## 실제 확인과 한계

개인 저장과 분리한 `/tmp/pokemon-challenge-review/`에서 Godot4.7.2로 실행했다. `/tmp` 증거·긴 로그·PNG는 커밋하지 않는다.

| 공개 행동 자동 정책 | 결과 |
|---|---|
| 기존 v27/시드2026 |69승·215턴·기절0·야영 물건6개|
| v28/동일2026 |69승·257턴·기절6·야영 물건14개·회복품2구매|
| v28/시드0,42 |각7승 뒤 첫 관장 패배·기절3/4|
| v28/카드 강화 우선 야영 준비0,42 |각7승 뒤 첫 관장 패배·기절3/3|

강화 정책은 전투 중 물건을 쓰지 않는다(이 게임 가방은 야영 전용). 강화·장비·회복을 준비해도 두 시드의 같은 단순 전투 정책은 첫 관장을 못 넘었다. 최초의 전투 중 가방 사용 시도는 거절되어 실질 준비 개선 근거에서 제외했다. 실패를 테스트 오류나 인간 평균 승률로 해석하지 않는다. 준비/포획/스타팅/상성·덱 선택을 최적화한 수동 플레이와 실제 평균 클리어율은 아직 측정하지 않았다. 종전보다 어려워졌고 정상 공개 행동으로 전체 클리어가 가능한 근거까지 확인했다.

- 최초 자동 묶음4,723/0: 실 v27 관장/사천왕/챔피언4저장 정확 복원/미래 상대 해시/동일 다음 입력/RNG/지문13항목 포함,새 원정 상태와 행동 검증. 마지막 중복 준비2026은 위 표의 추가 표본으로 세지 않는다.
- 수정한 야영 준비 두 시드615/0. 같은 전투 정책의 준비 효과가 제한적임을 확인했다.
- `tests/test_challenge_contracts.gd`245/0:69전 노드·파티/레벨/패턴 보존,개시 보호막,일반/전용 보스 공격의 최종 예고=실제 피해,새 규칙 실제 파일 저장/동일 다음 입력,필드 변조 거부,기존50%/신규30% 휴식.
- `tests/native_challenge_review.gd`: 제목 고지/실제 클리어 경로의 챔피언 개시 보호막/야영30% 문구와 OS 클릭을 확인하는 작은 X11 검사. UI 야영 HP는 fixture다. 최종9/0·1 OS클릭·3PNG 시각 확인을 마쳤다. 처음에는 검사 스크립트 타입 추론과 이미 사용한 야영 행동 fixture를 바로잡았으며 게임 로직 오류는 없었다.

재현은 `CHALLENGE_REVIEW_DIR`와 격리XDG를 지정하고 `test_campaign_challenge.gd`를 실행한다. `CHALLENGE_PREPARED_ONLY=1`은 준비 두 시드만 실행한다. 옛 저장 비교는 사전 캡처 `/tmp/pre-challenge-v27.bin`,계약과 창은 최초 묶음의 실제 새 보스 스냅샷이 필요하다. 이 증거가 없으면 과거 결과를 자동 반복하지 말고 해당 커밋/기록을 참조한다.

## EXE 제작

공식4.7.2캐시와 `tools/build_windows.py`로 격리소스 import/Windows x86_64 release 및 별도 검사용 export를 만든다. 게임 아이콘6크기/PE/PCK를 확인하며 안내·변경사항·에셋 출처·폰트/울음소리/Showdown/엔진 라이선스를 함께 배포한다. ZIP은 `PokemonExpedition.exe`와 `.pck`를 함께 풀어서 실행하며 Godot 설치는 필요 없다.

`tools/verify_export.py --mode linux-pack`는 배포 파일 SHA/실제 배포 PCK와 검사 PCK의 게임 항목 일치/정상 시작/리소스·저장·설정 동작을 공식 Linux release template로 확인한다. Windows EXE 자체의 실기 실행을 뜻하지 않는다. 현재 환경의 GitHub API 접근이 Forbidden여서 Windows CI를 실행하지 못했다. 수동 workflow를 자동화로 바꾸거나 제한을 우회하지 않는다. 실제 배포 결과는 인계의 EXE 기록을 확인한다.
