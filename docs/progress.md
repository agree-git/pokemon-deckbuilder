# 개발 진행 현황

새 대화에서 이어갈 때에는 [현재 작업 인계](../HANDOFF.md)를 먼저 읽는다.

현재는 **시작부터 챔피언까지 플레이 가능한 초기 알파**다. 전체 진행을 연결한 뒤 전투의 선택과 콘텐츠 품질을 다듬는 단계이며, 출시 준비가 끝난 상태는 아니다. 퍼센트 대신 실제 구현 범위와 남은 작업으로 관리한다.

## 아직 완성되지 않은 부분

- **빌드의 폭과 밸런스:** 공용 카드·유물·지닌 물건은 첫 구성이다. 같은 파티가 보상에 따라 다른 운영을 하도록 조합을 늘리고, 보상 가치·상점·회복 경제·초반 관장 대진·플레이 시간을 조정해야 한다.
- **원작 규칙의 깊이:** 386종과 354개 기술의 데이터가 있으나 기술 효과 일부는 카드 전투용으로 간소화했다. 비·눈·쾌청·모래바람의 기본 규칙은 구현했다. 개별 특성·날씨별 기술 예외·확률·고정 피해·다단 공격 등을 모두 원작처럼 재현하지 않았다. 지원 범위의 진화 184경로를 연결했으며 개별 특성·기술의 원작 효과 재현은 계속 확장해야 한다.
- **적의 개성:** 인물별 파티 전술을 구현했다. 아홉 가지 공통 유형을 조합한 첫 구성이며 124대진 고유 대사와 75대진 원작 도트를 연결했다. 후대 49대진 도트는 후보 링크 확인까지 진행했으며 원본 검토/적용이 남았다. 인물 전용 카드·고유 보상과 체력 구간별 변화는 후속 단계다.
- **희귀 콘텐츠:** 세 등급 21종의 조건부 도전·포획·영구 해금을 연결했다. 종별 전용 대사·유적 그래픽·특성·전용 보상과 희귀 스타팅의 반복 플레이 균형은 후속 단계다.
- **완성도·배포:** 바이옴별 음악 변주·분위기 소리 등 사운드 콘텐츠, 장시간 수동 플레이와 파티별 난도 검증, Windows 실행 파일·내보내기·호환성 검증이 남아 있다. 현재 실행 검증은 Linux/Godot 4.7.2 기준이다.

## 다음 개발 순서

**최신 사용자 지시에 따라 밸런스 조정과 추가 난도 측정은 뒤로 미룬다.** 기존 측정 보고서는 참고 자료로 보존하며 다음 요청에서 적 하향·초반 덱/경험치/경제 조정을 자동으로 이어가지 않는다.

1. 사용자에게 제공한 6세대 이후 도트 후보를 검토하고 원본 확인·제작자 표기·적용을 이어간다. 124대진 대사와 75대진 원작 도트는 완료했다. 이후 희귀 포켓몬의 이벤트/유적 등 콘텐츠를 보강한다.
2. 공용 카드·유물의 폭과 바이옴별 분위기 소리·음악 변주 등 완성도를 높인다. 여섯 콘셉트 24카드/12유물과 날씨 4카드, 장면별 음악·효과음·386종 울음소리·네 음량 항목은 완료했다.
3. Windows 빌드·내보내기·실제 실행으로 배포 전 검증을 진행한다.

각 단계에서도 최대 3마리 스타팅·69전투·경험치 성장·챔피언 전원 Lv.100·자동 저장을 유지한다. 자유 분기 지도나 4세대 이후 종을 현재 범위에 조용히 추가하지 않는다.

## 이번 작업과 검증 기록 — 보스 대사와 트레이너 도트

[보스 연출](trainer-presentation.md): 124대진의 역할별 고유 한국어 대사 372개를 등장·마지막 포켓몬 출전·승리 결과에 연결했다. 짧은 입력 잠금 연출과 기존 속도 설정을 사용한다. 실제 ID/출신 지역/전문 타입을 전달하며 같은 인물의 역할을 혼동하지 않는다. 원작 도트 73장/75대진은 원본 픽셀을 유지하고 알파 발끝·정수 배율·오른쪽 파티 여백을 적용했다. 공 투척·출전은 유지한다. 일반 상대와 후대 미적용 49대진은 자체 도트다.

- Godot 4.7.2/Linux: 콘텐츠/글꼴/알파/전체 자세/순수 조회 3,561개, 헤드리스 UI 138개, 실제 X11 UI 156개(15클릭/10키), 기존 등장 64개와 앞선 대사 연결 시점의 저장 회귀 1,759개 통과. 세 연출 속도와 원작 도트/공용 도트, 실제 카드로 마지막 적 교대/승리/재개/입력 잠금을 확인했다. 최종 오류/잔여 리소스 없는 로그, PNG 73개 SHA/대응 목록과 사용자 배경 좌표 SHA를 확인했다. 사람 난도/Windows 검증은 하지 않았다.
- [1920×1080 검토 화면 18장·전체 도트 대응·CSV·ZIP](https://github.com/agree-git/pokemon-deckbuilder/blob/trainer-dialogue-review-2026-10-17/review/trainer-presentation/README.md)을 별도 브랜치에 둔다. 마지막 출전/결과는 HP 1 fixture다.
- 사용자 추가 요청의 [6세대 이후 사이트·개별 도트 링크](trainer-sprite-links.md)를 제공했다. Showdown 갤러리에서 48대진의 제작자/파일명 등재와 제작자 표기·무단 편집 금지 조건을 확인했다. 시트론은 별도 확인이 필요하다. 현재 네트워크가 Showdown 이미지 서버를 403으로 차단해 후보 파일은 다운로드/시각 검토/적용하지 않았다. 기존 원작 PNG와 팬 제작 후보를 구분해 기록했다.

## 직전 작업과 검증 기록 — 선명한 전장 날씨와 왼쪽 위 햇살

[전장 날씨 연출](weather.md)을 강화했다. 단순 배경 색조에서 배경·포켓몬 전체에 합성하는 별도 레이어로 바꾸고, 사용자 추가 요청에 따라 전체 효과를 조금 더 선명하게 했다. **쾌청은 왼쪽 위의 후광에서 빛이 펼쳐지고 대각선 렌즈 플레어로 이어진다.** 비는 앞/뒤 빗줄기·바닥 물결, 눈은 크기·속도가 다른 눈송이·찬 안개, 모래바람은 가로 먼지층·빠른 알갱이를 사용한다.

- 새 `BattleWeatherVisual`은 3px 도형 격자와 0.55초 전환/종료를 사용한다. 반복 HUD 갱신은 전환을 재시작하지 않는다. 기술/포켓볼 연출과 HUD는 위에 표시하고 상단 바·손패 경계를 제외한다. 필드 하단은 점차 옅게 처리한다.
- 실제 렌더러 97개·헤드리스 전장 31개·실제 X11 날씨 카드 33개/12클릭, 기존 날씨 규칙/저장/획득 121개·전투 연출 28개를 확인했다. 야외/리그 실내 두 배경, 세 창 비율, 실제 픽셀의 상단/손패/파티 글자 보호, 왼쪽 위 광원, 움직임/결정적 재현, 전투 상태/난수/사용자 좌표 보존을 검사한다. 기존 연출 테스트의 종료 시 장면/오디오 정리 절차도 보완했다. 최종 로그의 오류/리소스 잔여 경고가 없음을 확인했다.
- [최신 날씨 화면 8장·ZIP](https://github.com/agree-git/pokemon-deckbuilder/blob/weather-field-review-2026-10-17/review/weather-field/README.md)은 같은 파티로 배경과 날씨를 바꾼 1920×1080 검토 장면이다. 정상 챔피언 대진/난도 자료가 아니다. Godot 4.7.2/Linux 기준이며 Windows 검증·밸런스 조정은 별도다. 기존 날씨의 5턴/피해/저장 규칙은 유지한다.

## 직전 작업과 검증 기록 — 여섯 콘셉트 확장과 전투 날씨

[여섯 콘셉트](build-concepts.md)의 **카드 24종·일반 유물 12종**, [날씨](weather.md)의 **공용 카드 4종**을 보상·상점·강화·미리보기·단계 연출·저장에 연결했다. 현재 **공용 카드 55종과 부상·일반 유물 26종·핵심 유물 5종·지닌 물건 6종**이다. 신규 수치는 초기값이며 기존 적 난도·성장/경제 조정과 추가 난도 계측은 보류한다.

- 교대·협동 / 에이스 집중 / 상태·지속 / 보호막·요새 / 소진·도구 / 순환·보존에 각각 카드 4종·유물 2종을 더했다. 전담 기술 회수, 다음 턴 에너지 비축, 기존 지속 상태 연장, 멤버별 보호막 1회 보존, 소진 도구 재사용, 최저 비용 카드 선별·전체 손패 보존과 재섞기 보상 등이다. 상세 조건/강화는 위 문서를 따른다.
- 비: 물 ×1.5·불꽃 ×0.5 / 쾌청: 반대 / 눈: 얼음 물리 방어 ×1.5·지속 피해 없음 / 모래바람: 바위 특방 ×1.5·출전 멤버 최대 HP 1/16 관통 피해·바위/땅/강철 면역. 양쪽 공통 한 종류, 5턴, 재사용 갱신/다른 날씨 교체, 상대 행동과 상태 처리 후 1회 경과, 교대 유지·전투 종료 해제다. 원작 #240/#241/#201/#258도 실제 날씨를 사용하며 #258은 현대 눈으로 통일했다. 특성/날씨별 기술 예외·바이옴 자동 날씨·적 날씨 행동은 후속이다.
- 새 지속 효과·비축·날씨는 기존 v3 `powers`, 턴당/멤버별 발동은 `turn_flags`로 저장한다. 날씨는 한 종류/1~5턴으로 검증한다. `BattleFrame`의 `powers` 사본으로 날씨/비축 HUD를 단계에 맞춰 표시한다. 모래 피해 양쪽 처리 후 기절/승패를 판정하며 강제 교대가 추가 tick을 만들지 않는다.
- 상단 날씨 아이콘·잔여 턴·툴팁·입자/색조, 카드 사용 예고·실제 피해/적 공격 예고를 연결했다. 일반 유물 26개+핵심 1개 메뉴를 스크롤하고 상단 유물 툴팁은 최근 3개로 요약한다. 직접 교대 할인 비용을 파티/도움말에 실제 현재값으로 표시한다. 사용자 배경 JSON SHA와 승인 타입 배지를 유지했다.
- Godot 4.7.2/Linux: 콘셉트 규칙/사본별 디스크 복원/획득 452개, 날씨 규칙/저장/획득 121개, 능력치 55개, 카드 설명 3,136개/876얼굴·미리보기 8,601개 통과. 기존 공유 덱 632개·앞선 확장 120개·조합 610개·핵심 357개·상점 1,199개도 통과했다. 원정/저장 회귀는 194개(세 시드 각 69승)/1,759개다.
- 실제 X11 포인터: 콘셉트 49개/32클릭, 27유물 메뉴/세 창 비율/할인 표시 43개/8클릭, 날씨 33개/12클릭. 헤드리스 UI는 각각 콘셉트 43개·날씨 32개다. 전체 import와 최종 로그의 오류/리소스 잔여 여부를 확인했다. 1920×1080 카드 갤러리 7장과 날씨 전투 예시 4장은 [검토 브랜치](https://github.com/agree-git/pokemon-deckbuilder/blob/concept-review-2026-10-17/review/build-concepts/README.md)에 둔다. 자동 완주는 사람의 승률·재미 보장이 아니며 Windows 실행과 수동 밸런스는 미완료다.

## 직전 작업과 검증 기록 — 네 빌드의 카드·유물 확장

[추가 카드·유물](build-payoffs.md) 4종씩을 전투·보상·상점·강화·저장에 연결했다. 현재 **공용 카드 27종과 부상·일반 유물 14종·핵심 유물 5종·지닌 물건 6종**이다. 밸런스 조정과 추가 난도 계측은 계속 보류하며 신규 효과 수치는 첫 구성이다.

- 카드: 연계 회수(살아 있는 대기 동료의 버린 기술 최신순 최대 2장/강화 3장), 결정타 지시(이번 턴 지정된 출전 멤버의 다음 공격 기술 2배·중첩 불가), 발병 촉진(적 화상·씨앗·독 즉시 1회·횟수 유지), 방벽 압축(현재 보호막 2배). 모두 소진이며 발병 촉진은 도구다. 나머지 셋의 강화는 비용 0이다.
- 유물: 인계 망토(첫 기술 자동 교대 시 보호막 이동), 돌파 훈장(같은 멤버의 세 번째 기술 에너지 +1), 배양 접시(새 지속 피해 종류를 걸어 둘 이상이 되면 2장 뽑기), 축전 방패(완전 방어 시 다음 아군 턴 에너지 +1). 첫/턴당 제한·소유자·손패 상한을 적용한다. 새 카드/유물 ID와 표식·충전은 기존 v3 목록/`turn_flags`에 저장하며 기존 보상/가격을 재추첨하지 않는다. `BattleFrame`에 플래그 사본을 넣어 연출 중 아이콘이 확정 결과로 먼저 바뀌지 않게 했다.
- Godot 4.7.2/Linux: 신규 규칙/저장/접근성 120개(보호막의 기존 v3 상한 100,000과 인계 후 미리보기 포함)·UI 헤드리스 12개/실제 X11 13개(10클릭), 아이콘 2,797개/792얼굴·미리보기 5,241개, 기존 공유 덱 632개·조합 610개·핵심 유물 357개·상점 1,199개를 통과했다. 기존 원정 회귀 194개(세 시드 각 69승)·원정 저장 1,759개, 15개 유물 메뉴의 실제 X11 39개(7클릭·휠·세 창 비율)도 통과했다. 자동 완주는 재미나 승률의 보장이 아니다. 늘어난 메뉴 검사는 유물 풀 크기에 맞춰 끝 항목을 검사하고 오디오가 끝나기 전 종료하던 기존 테스트의 정리 절차를 고쳤다.
- 모바일 검토용 원본 크기 카드 갤러리는 `images/build-payoffs.png`다. 실제 전투에서도 새 카드와 유물을 클릭해 실행했다. 사용자 배경 JSON과 승인 타입 에셋은 유지했다. 일반 유물의 후반 수렴·더 넓은 콘텐츠 풀, 수동 플레이/Windows 검증은 남아 있다.

## 직전 작업과 검증 기록 — 386종 울음소리와 독립 음량

[포켓몬별 울음소리](cries.md) #001–386을 파일에 포함하고 첫 등장·포켓볼 교대에 연결했다. 아군 등장 후 야생 상대가 울고, 트레이너 상대는 공에서 나타날 때 운다. 수동/기술 자동 교대와 다음 적은 새로 표시된 종으로 재생한다. 행동을 시작하면 남은 야생 등장 예약을 취소하고 회수·전투 이탈·장면 전환 시 잔여 소리를 정지한다.

- `GameCries`는 아군/적 두 플레이어, 최근 12종 캐시, `Cries → Game → Master` 버스와 고정 게인 0.35를 쓴다. 울음소리 기본 75%·별도 저장·피카츄 미리 듣기를 추가하고 설정창을 네 음량 행에 맞췄다. 음악/효과음 음량과 독립적이며 음소거·0%는 재생 요청을 버린다. 전투 배율은 음높이를 바꾸지 않는다. 모델·게임 난수·저장·성장·경제는 그대로다. **밸런스 조정·추가 난도 계측은 계속 보류한다.**
- 원본은 PokéAPI/cries `latest`의 고정 커밋이며 원본 README/LICENSE·원본/포함 파일 SHA·전체 디코딩 PCM SHA·길이를 보관했다. #025는 원본 확장자와 다른 MP3 비트스트림을 Ogg로 변환했다. 나머지 385개는 원본 그대로다. 약 5MB이며 실행 중 다운로드하지 않는다. `tools/fetch_pokemon_cries.py --check`는 오프라인으로 386개 전체 디코딩과 지문·모음 무결성을 검사한다. 기존 직접 합성한 음악/효과음과 출처를 구분한다.
- Godot 4.7.2/Linux: 울음소리 417개(386개 import·비루프·12종 캐시·두 플레이어·실제 PCM 음량/음소거·아군 자동 교대·다음 적·트레이너 투척·실제 장면 교체·모델/난수 불변), 설정 32개·효과음 50개·음악 42개, 설정 UI 헤드리스 40개·실제 X11 44개(35클릭·세 창 비율)를 통과했다. 별도 프로세스 저장/시작 복원과 386개 원음 전체 디코딩·지문/모음 무결성을 확인했다. 실제 믹서 피크는 전체/울음소리 1/1에서 0.35644, 1/0.5에서 0.17822, 0.5/0.5에서 0.08600, 음소거에서 0이다. 종료 시 스크립트 오류·리소스 잔여 경고가 없는 로그를 확인했다.
- 검토 자료는 `audio/cries-preview.mp3`(14종 전체 길이 모음)와 갱신한 `images/settings.png`다. 사용자 배경 JSON SHA와 승인 타입 배지를 유지했다. 클라우드 검사는 Dummy 믹서 PCM이며 실제 스피커 청음·Windows 오디오 장치 검증은 별도 미완료다.

## 직전 작업과 검증 기록 — 장면별 음악과 이어 듣기

[장면별 배경 음악](music.md) 5곡을 직접 제작했다. 시작/스타팅·야영지/보상·일반 전투·관장/사천왕·챔피언에 다른 8마디 곡을 재생한다. 두 음악 플레이어로 0.55초 전환하고 같은 곡 요청/화면 갱신은 재시작하지 않는다. 같은 프레임의 여러 요청은 마지막 곡으로 모으고 빠르게 이전 곡으로 돌아가면 아직 재생 중인 위치를 활용한다.

- `GameMusic` 자동 로드와 `Music → Game → Master` 버스를 추가했다. 음악 기본 55%를 별도 저장하며 이전 설정 파일에도 기본값을 적용한다. 음악/전체 0%·음소거는 음악 위치를 일시 정지하고 켜면 현재 장면으로 이어간다. 효과음 음량과 전투 배율은 음악 음량/음높이에 영향을 주지 않는다. 전투 결과는 규칙 확정 순간이 아닌 마지막 연출이 끝날 때 편안한 곡으로 전환한다.
- Python/FFmpeg 생성 도구·PCM/파일 지문 manifest·22.05kHz 16비트 WAV 5개와 모바일 MP3 모음을 추가했다. import에서 정방향 루프·무압축을 지정한다. 음악 서비스는 미리 로드한 데이터와 노드 수를 유지하고 게임 모델·난수·성장/경제·원정 저장을 바꾸지 않는다. **밸런스 조정과 추가 난도 계측은 계속 보류한다.**
- Godot 4.7.2/Linux: 음악 42개(실제 루프 경계·빠른 전환·이전 곡 재사용·무음/복원·믹서 배율·실제 6종 전투/야영지/시작·승리 시점·모델 불변), 설정 32개·효과음 50개, 설정 UI 헤드리스 34개·실제 X11 38개(30클릭·음악 슬라이더/화살표·세 창 비율)를 통과했다. 별도 프로세스 음악 음량 복원과 원음/MP3 지문·파형/루프 끝점을 확인했다. 종료 시 리소스 참조가 남던 초기 전환/생명주기 처리를 정리하고 최종 검사에서 기능 실패와 리소스 잔여 경고가 없는 로그를 확인했다.
- 검토 자료는 `audio/music-preview.mp3`와 `images/settings.png`다. 사용자 배경 JSON과 승인 타입 배지를 유지한다. 클라우드 검사는 Dummy 믹서의 PCM 출력이며 실제 스피커 청음·Windows 실행·바이옴별 분위기 소리·포켓몬별 울음소리는 아직 미완료다.

## 직전 작업과 검증 기록 — 전투 효과음과 음량 설정

[전투 효과음](audio.md) 15종을 직접 합성하고 카드·공격 준비·피해·완전 방어·보호막 획득·회복·포켓볼 회수/등장·상태/유물·기절·포획·턴·승패 결과에 연결했다. 이미 확정된 표시 이벤트의 재생 시점에 소리를 내며 규칙 확정 순간에는 소리를 내지 않는다. 1/1.5/2배에서도 단계 순서와 원래 음높이를 유지한다.

- 공통 설정에 전체/효과음 0~100% 슬라이더·음소거·미리 듣기와 저장/시작 복원을 추가했다. 기본값은 전체 75%·효과음 80%이며 이전 설정 파일에는 기본값을 적용한다. 슬라이더의 클릭/드래그·포커스된 좌우 화살표 1% 조절을 지원한다. 음소거/음량 0은 현재 소리를 정지하고 지나간 소리를 쌓아 두지 않는다.
- `GameAudio`는 `Effects → Game → Master`의 버스와 전투 6·UI 1개의 제한된 플레이어를 재사용한다. 장면 전환 시 잔여 소리를 끈다. `BattleSoundCues`는 확정된 이벤트에서 소리만 고르고 게임 난수·전투/경제/성장·원정 저장은 바꾸지 않는다. `tools/generate_sound_effects.py`로 44.1kHz·16비트 PCM을 재현하며 외부 게임 음원을 다운로드하지 않았다.
- Linux / Godot 4.7.2: 오디오 50개, 설정 32개, 설정 UI 헤드리스 29개·실제 X11 33개(27클릭·세 창 비율·화살표·미리 듣기/음소거)와 기존 연출 28개를 통과했다. 별도 프로세스의 화면/연출/오디오 복원, 15종 PCM·페이드·피크·서로 다른 원음/모음의 재현성을 검사했다. 실제 믹서 피크는 전체/효과음 1/1에서 0.16309, 0.5/1에서 0.08155, 0.5/0.5에서 0.04077, 음소거에서 0이다.
- 검토 자료는 `images/settings.png`와 `audio/effects-preview.wav`다. 전체 import와 사용자 배경 JSON 원본 해시를 유지한다. 클라우드는 Dummy 출력에서 PCM을 캡처했으며 실제 스피커 청음·Windows 오디오 장치·배경 음악·포켓몬별 울음소리는 미완료다. **밸런스 조정·추가 난도 계측은 계속 보류한다.**

## 직전 작업과 검증 기록 — 공통 설정과 전투 연출 옵션

[화면·전투 연출 설정](settings.md)을 구현했다. 시작 화면·스타팅 선택의 톱니바퀴, 전투의 Esc 메뉴, 야영지 등 원정 화면의 톱니바퀴에서 같은 창을 연다. 창 모드/최대화/전체 화면과 F11, 전투 연출 1/1.5/2배, 피격 흔들림 켜기/끄기를 제공한다. `user://settings.cfg`에 별도 저장하고 다음 실행 시 복원한다. 저장 오류 안내·재시도와 잘못된 값의 기본값 복귀를 포함한다.

## 직전 작업과 검증 기록 — 사용자 수정 좌표 적용과 재촬영

사용자가 HTML에서 수정해 올린 [배경 좌표](battlefield-layout.md) 파일을 바이트 그대로 적용했다. 48개 중 26개 셀(아군 25·상대 23)이 달라졌고 SHA-256은 `b0f2e796afbb02eb04bef728ae28cfd113b1b8a8d6939911d5d0371ba89724f3`다. 소수점도 보존하며 297.6/287.2를 먼저 Vector2로 바꿔 카메라가 1px 달라지는 문제를 함께 수정했다. 가이드 좌표도 소수 한 자리로 표시한다.

HTML 수정 도구 초기값도 사용자 좌표다. 전투/저장/배경 PNG는 바꾸지 않았고 Windows 실행/사람 밸런스는 별도다.

## 직전 작업과 검증 기록 — 독립 HTML 배경 위치 수정 도구

기존 접지가 전체적으로 어긋난다는 사용자 피드백 이후, 직접 배경을 보며 이동할 수 있는 [HTML 파일](battlefield-editor.md)을 제공한다. 48개 배경·386종 앞뒤 772개 PNG를 포함한 약 28MB 독립 파일이다. 마우스/터치 드래그·클릭·숫자·방향키 수정, 되돌리기/다시 하기, 배경별 초기화, 게임 구도 미리보기와 JSON 입출력·CSV·PNG 저장을 구현했다. 임시 저장은 브라우저가 허용할 때만 사용하며 JSON으로 보관할 수 있다.

Linux Chromium에서 네트워크를 차단한 문서로 **1,046개 검사**를 통과했다. 48개 룸·원본 이미지 바이트·실제 마우스/터치·좌표 배율·이력·모드 잠금·다운로드/불러오기/거부를 확인했으며 실제 Godot 촬영 메타데이터의 48개 접지점/정수 배율과 비교했다. 별도 로컬 HTTP에서 임시 저장/새로고침 복원을 확인하고 데스크톱/모바일 화면을 시각 검토했다. 관리 브라우저의 file:// 탐색은 관리자 정책으로 차단되어 문서 삽입과 로컬 HTTP로 검사했다. iOS/Safari는 검증하지 않았다. Godot 4.7.2 프로젝트 import 오류는 0개다.

재현 소스/검사는 main, 큰 HTML/ZIP/미리보기는 별도 검토 브랜치에 보관한다. 현재 게임 좌표·PNG·전투·원정·저장은 바꾸지 않았고 기존 65장 갤러리/ZIP/CSV도 재촬영하지 않았다. 이 도구 제공은 기존 접지가 수정/승인되었다는 뜻이 아니다. 사용자 수정 JSON 적용 후 실제 게임 재촬영이 다음 작업이다.

## 직전 작업과 검증 기록 — 전 지방 관장 후보와 GitHub 검토 자료

[관장 후보](gyms.md)를 82팀·83명으로 확장했다. 공동 풍·란·혼합 그린·버전 차이·전임/후임·마이너리그·팔데아 타임을 포함한다. 각 바이옴은 타입별 후보에서 시드로 선정하고 세 보스 역할의 인물 중복을 막는다. 1~3세대·각 6종·비전설/비환상·69전투·레벨/XP는 유지한다. 총 보스 전술 정의는 124개다.

`route_version` 부재인 이전 v3는 기존 1번 경로/서명을, 새 원정은 2번 후보를 사용한다. `gyms.json`의 18개 기준 편성/콘텐츠 지문을 유지하며 기존 원정·미래 대진을 바꾸지 않는다. 새 후보/선정 코드를 측정 지문에 추가했고 이전 난도 보고서는 당시 대진 자료로 구분했다.

Linux/Godot 4.7.2 import, 후보/512개 시드 16,310개·보스 12,864개·저장 1,759개·파일 23개·이전 능력치 저장 390개·비주얼 6,805개·진단 47개·별도 프로세스 저장/복구 5단계 28개를 통과했다. 실제 렌더러에서 8지방·그린·타임의 독립 장면 10개/62개 검사를 통과했다. 전체 69전투·엔딩 UI 입력 2,487개(포인터 1,971·키 336, headless 주입)를 통과했으며 타임 추가 전후 해당 시드 2026의 대진 서명은 같다. Windows 실행/사람 밸런스 검증은 별도다.

## 직전 작업과 검증 기록 — 손패·전투 구도·리그 실내 배경

손패는 5장까지 나란히, 6~10장은 한 줄 안에서 겹친다. 호버한 카드는 위로 34px·10% 확대되고 양옆 카드가 벌어진다. 선택 카드의 가로 위치는 유지해 포인터에서 도망가지 않으며 이탈·사용·드로우 뒤 재정렬한다. [손패·연출](battle-presentation.md)을 따른다.

바이옴 18종을 굵은 도트와 단순한 색면으로 다시 그렸다. 같은 높이로 그려진 발판을 수정하고 아군은 왼쪽 아래, 적은 오른쪽 위에 놓았다. 상시 상하 흔들림을 제거하고 투명 여백을 제외한 발끝과 접지 그림자를 맞춘다. HP가 발을 가리지 않게 옮기고 큰 적의 행동 예고는 머리 위 공간에 따라 위/옆에 놓는다.

트레이너·관장·리그에는 등장→준비→볼 투척→출전→퇴장을 넣고 도입 중 입력을 잠근다. 착지한 볼에서 출전하므로 두 번 던지지 않는다. 같은 전투를 다시 그려도 반복하지 않는다. 사람은 역할·타입 색별 공용 자체 도트 캐릭터이며 개별 원작 인물 외형은 미구현이다. [리그 실내 배경](league-stages.md)은 타입 룸 18개(현재 사천왕 14타입 사용)와 현재 챔피언 11명의 8개 지방 변형을 연결한다. 야영지·대진·레벨·XP·보상·저장 형식은 유지한다.

화면·UI는 **1920×1080**이다. 배경 원본은 1536×1024 아틀라스의 약 768×341 셀이며 개별 1920×1080/정확한 16:9 원본이 아니다. 최근접 확대·전투 지형 프레이밍·손패 위 페이드를 사용한다. 이 차이를 사용자에게 설명했고 [출처](../ASSET_SOURCES.md)에 생성 이력과 해시를 갱신했다.

**검증:** Linux/Godot 4.7.2 import, 실제 X11 손패 292개(포인터 이동 53·클릭 5), 트레이너 도입 65개, 덱 UI 43개(포인터 70·키 7), 리그 배경 규칙 164개, 기존 연출 26개를 통과했다. 전체 UI 입력 69전투·엔딩 2,524개 검사(포인터 2,001·키 346)를 통과했고 별도 공개 행동 원정도 69승·리그 5개 화면을 캡처했다. 손패 확대·투척·접지·에스퍼 실내·가라르 챔피언 경기장을 1920×1080 실제 렌더링으로 검토했다. Windows 실행은 미검증이다.

### 전투별 난도 진단

[40개 진단](measurements/campaign-battle-diagnostics.md)은 시작 파티·실제 공격/발버둥·상대별 상성과 정산 전 HP·기절·카드 사용을 남긴다. 관동 10/10·물 보조형 0/10·잉어킹 단독 0/10·아기 1/10 완주, 미완료 0개이고 기존 160개 중 해당 40개 결과 필드가 모두 같다. 규칙·자동 정책·적 수치를 조정한 측정은 아니다. 진단 47개·보고서 17개 검사를 통과했다. 해석과 다음 조사 범위는 [난도 측정](balance-measurements.md)을 따른다.

## 이전 타입 아이콘 적용 기록

사용자가 미리보기를 검토·승인한 **웹 타입 기호 18종**을 기존 타입 아이콘 자리에 적용했다. 원본 SVG 경로를 유지하고 원본 CSS 색상·여백으로 32px 원형 배지를 만들었다. 전투 HUD·카드·파티/스타팅·준비 화면 등 공통 아이콘 사용처에 적용되며, 게임 전체 화면은 1920×1080을 유지한다. 원본 README·CSS·SVG, 고정 URL·SHA-256·변환 내역을 [에셋 출처](../ASSET_SOURCES.md#ui-아이콘)와 `assets/sources/type_icons.json`에 기록했다. `tools/import_type_icons.py --offline`으로 재현하고 `--check`로 검증한다. 실행 중 다운로드는 없다.

## 이전 덱 필터·인계 지침 검증 기록

원정 덱 조회·카드 강화·상인 제거를 [같은 카드 그림과 소유자 필터](deck-browser.md)로 통일했다. 전체/공용/각 동료별 실제 사본 수를 표시하며 중복은 겹친 카드와 ×N으로 묶는다. 강화도 이름 행 대신 카드 그림을 선택하며, 확인을 취소하면 같은 필터로 돌아간다. 선택한 한 UID만 강화/제거하고 기본/강화 사본은 분리한다. 강화 불가능한 카드·부상·제거 제한과 빈 목록을 안내한다.

## 이전 카드 제거 확인 검증 기록

상인 야영지에 [카드 제거 확인](camp-removal-preview.md)을 추가했다. 이름 목록에서 즉시 제거하던 흐름을 **겹친 카드 목록 → 선택한 한 장의 변화 확인 → 확정**으로 바꿨다. 기본/강화·소유자를 구분하고, 같은 사본 수·덱 장수·골드·다음 실제 상대별 공격/약점/지속·조건부 카드 수를 보여 준다. 마지막 유효 직접 공격이 사라지면 붉게 안내한다.

목록으로·닫기·바깥 클릭·Esc는 조회만 취소하며, Enter는 확정하지 않는다. 확정은 현재 가격·자금·방문당 한 장 제한·최소 덱·동료의 마지막 기술 보호를 기존 공개 행동으로 다시 검사한다. 실제 한 장과 비용만 처리하고 자동 저장하며 휴식·강화는 남겨 둔다. 가격·전투·성장·경로·난수·저장 형식은 바꾸지 않았다. 기술 교체 비교와 제거 확인은 같은 다음 상대 집계·카드 표시를 사용한다.

제거 규칙/미리보기 111개·실제 X11 UI 65개 검사(포인터 27회·Enter 3회·Esc 6회)를 통과했다. 세 창 비율의 카드 얼굴 위/중간/아래 클릭, 중복 묶음·강화·모달 차단·취소·실제 한 장 제거·자동 저장·확정 시 비용 부족·최소 덱·마지막 기술 보호를 확인하고 1920×1080 선택/마지막 공격 안내 화면을 검토했다. 기술 비교 규칙 349개·준비 81개·카드 묶음 11개·상인 1,199개·저장 1,771개와 덱 원정 194개(시드 0/42/2026의 69전투 완주)도 통과했다.

실제 X11 기술 비교 UI 58개·상인 UI 31개·강화 비교 UI 27개를 통과했고 기존 덱 UI 35개·강화 비교 UI 26개 회귀 검사도 통과했다. Linux/Godot 4.7.2 기준이며 수동 밸런스·Windows 검증은 남아 있다.

## 이전 기술 비교·카드 묶음 검증 기록

기술 습득 화면에 [교체 전후 비교](learning-comparison.md)를 추가했다. 옛 기술과 학습 후 기술의 실제 사본·비용·소유 포켓몬·강화를 나란히 확인하고, 다음 상대별 통하는 공격·약점·지속/조건부 카드 수의 변화를 확인한다. 원본 사본이 0장이면 새 기본 카드 한 장과 덱 증가를, 사본이 있으면 실제 강화 보존을 보여 준다. 비교 창의 Q/W/E/R은 대상만 선택하며 확인 버튼으로 배운다. 목록으로·닫기·Esc는 미확정 상태로 돌아간다. 습득 화면의 직접 기술 선택과 Q/W/E/R도 사용할 수 있다.

현재 파티·살아 있는 동료·이번 선택 한 건의 상성 비교다. 마지막 유효 공격 상실을 표시하고, 다음 야영지 회복·미결정 학습·영입 교체·피해량·승률을 예측하지 않는다. 실제 학습·덱·경험치·전투 규칙·난수·저장 형식은 그대로다. 원본과 분리한 가상 카드로 계산하며 조회만으로 실제 ID를 발급하지 않는다. 카드가 없는 비교/준비 탭의 설명문이 폭 0으로 가려지던 표시도 수정했다.

덱·남은/버린/소진 더미·출발 덱·합류 미리보기·전투 준비·기술 비교에서 같은 소유자·강화·내용의 카드를 **겹친 테두리와 ×N**으로 묶었다. 실제 사본·순서·장수는 보존하고 기본/강화·서로 다른 소유자는 구분한다. 원정 덱 조회도 카드 얼굴로 바꿨다. 개별 인스턴스를 사용하는 손패와 강화/제거 선택은 기존처럼 동작한다.

규칙 349개와 준비 규칙 81개·기술 카드 48개·묶음 표시 11개 검사를 통과했다. 실제 X11 비교 UI 58개 검사·포인터 24회·단축키 10회와 Esc 3회로 세 창 비율의 클릭, 네 후보 비교, 중복 사본 묶기·강화 분리·원본 없음 안내·모달 차단·Enter 오확정 방지·취소·확정·자동 저장을 확인했다. 1920×1080의 사본 없는 경우와 여섯 상대 비교 화면을 검토했다. 준비 UI 38개·합류 UI 34개·출발 덱 UI 36개·덱 UI 43개의 실제 X11 검사를 통과했다. 덱/더미의 전체 장수·필터·스크롤·취소·조회 불변성과 실제 강화·전투 진행을 확인하고 덱/더미/준비의 묶음 화면을 검토했다.

세 별도 프로세스의 미확정 저장 → 재실행/비교/습득 → 재실행/실제 물대포 사용·승리/XP 검사 21개를 통과했다. 관동/혼합 편성 × 시드 5 × 두 영입 정책의 네 원정에서 매 학습 시 모든 교체 후보를 조회해도 전체 상태가 같았고, 각각 69전투·챔피언까지 완료했다. 이전 측정의 모든 필드·규칙 지문과 일치했다. 저장 1,771개·성장 UI 88개·기존 기술 UI 22개·강화 비교 UI 26개·전투 연출 26개 회귀 검사도 통과했다. Linux/Godot 4.7.2 기준이며 수동 밸런스·Windows 검증은 남아 있다.

## 이전 다음 전투 준비 검증 기록

지도·야영지에 [다음 전투 준비](encounter-preparation.md)를 추가했다. 실제 상대 파티를 선택해 **통하는 공격·타격 무효·지속/조건부** 카드를 카드 얼굴로 확인하며 복합 상성·약점 사본 수를 표시한다. 배운 기술만 보고 공격 수단이 있다고 판단하지 않고 실제 원정 덱을 읽는다. 기절한 소유자의 기술은 제외하며 회복 후 다시 조회한다. 예약한 희귀 조우도 실제 종·레벨·장소를 표시한다.

상성 조회는 피해량·승률 예측이 아니며 직접 공격이 없으면 카드 부족 또는 조건부 확인을 안내한다. 발버둥의 중립 타격, 현재 전투의 지속 효과와 보호막 전환/상태 회수 준비 조건을 구분한다. 창을 닫고 휴식·가방·구매·장비 준비를 계속할 수 있으며 출발을 막거나 덱을 대신 바꾸지 않는다. 기존 상성·전투 규칙·경험치·대진·저장 필드와 난수는 그대로다.

규칙 81개와 실제 X11 UI 38개 검사·포인터 25회로 세 창 비율의 위/중간/아래 클릭, 마지막 상대 선택·카드 탭·긴 목록 스크롤·모달 차단·닫기/Esc·자동 저장 보존, 실제 휴식 후 기절 카드 재집계를 확인했다. 1920×1080 공격/무효/조건부 화면을 검토했다. 관동/혼합 편성 × 시드 5 × 두 영입 정책의 4개 원정은 모든 지도·야영지에서 준비 조회 전후 상태가 같았고 각각 69전투·챔피언을 완료했다. 이전 측정의 모든 결과 필드와 규칙 지문이 일치했다.

저장 1,771개·야영지 UI 48개·희귀 UI 47개·기술 카드 UI 22개를 통과했다. 고정 시드 0/42/2026도 각각 69전투·엔딩과 덱 원정 194개 검사를 통과했다. 현재 검증은 Linux/Godot 4.7.2이며 파티별 수동 밸런스·Windows 검증은 남아 있다.

## 이전 기술 카드 누락 수정 기록

고스트 장기 전투를 재현해 **배운 기술은 바뀌었으나 카드가 덱에 들어오지 않는 문제**를 수정했다. 옛 기술 사본이 상점 제거로 0장인 상태에서 새 기술을 수락하면 이제 기본 카드 한 장을 새 ID로 지급한다. 기존 사본이 있으면 모든 사본의 ID·소유자·강화를 유지해 변환한다. 배우지 않기는 카드와 기술을 유지한다. 상성·능력치·성장·볼 비용·자동 전투 정책을 바꾸지 않았다.

[기술 습득 화면](growth.md#레벨별-기술과-교체)은 새 기술의 실제 카드 얼굴·효과·소유 포켓몬과 교체 후보별 실제 사본 수, 사본 없음의 한 장 추가, 툴팁의 덱 장수 변화를 표시한다. 규칙 48개와 실제 X11 UI 24개·포인터 4회로 세 창 비율의 위/중간/아래 클릭·실제 확정/거절·자동 저장을 확인하고 1920×1080 화면을 검토했다. 세 별도 프로세스에서 미확정 선택 → 이어하기/새 카드 생성 → 다시 이어하기/실제 카드 사용·승리/XP를 확인했다(19개 검사). 과거 누락과 의도적인 제거는 구분할 수 없어 기존 덱을 불러올 때 자동 복구하지 않으며 이후 학습부터 적용한다.

[수정 후 비교 160개](measurements/campaign-learning-deck.md)는 모두 종료했다(36 완주·124 실제 전멸). 혼합·시드 5·초반 영입은 수정 전 고스트 야생 200턴 중단에서 수정 후 번개쇼크/스파크를 실제 사용한 69전투·챔피언 완주로 바뀌었다. 벌레·시드 2·초반 영입과 이상해씨 단독·시드 3·영입 없음도 완주했다. 관동은 두 영입 정책 모두 10/10, 물 보조형·잉어킹 단독은 여전히 0/10이다. 규칙 지문별로 이전 결과를 분리해 보관한다. 별도 프로세스 18개 재측정에서 모든 필드·지문이 일치했다.

성장 42,937개·저장 1,771개·이전 능력치 저장 390개·영입 479개·시작 UI 26개·성장 UI 88개·보고서 14개 검사를 통과했다. 성장 UI의 옛 상점 배열 인덱스를 실제 상처약 버튼 이름으로 바꿔 구매/소비 검사를 유지했다. 고정 시드 0/42/2026은 각각 69전투·엔딩과 덱 원정 194개 검사를 통과했다. Linux/Godot 4.7.2 기준이며 파티별 수동 밸런스·Windows 검증은 남아 있다.

## 이전 영입 미리보기 검증 기록

[포획 후 합류 미리보기](recruitment.md)를 추가했다. 실제 추가/제거 카드 얼굴과 소유 포켓몬·강화·부상, 합류 후 덱 장수, 반환 장비를 보고 편성을 확정한다. 빈자리는 기존 파티를 보존한다. 목록으로·Esc·바깥 클릭은 조회만 취소하며 포획 대기·영구 해금을 유지한다. 확정만 실제 파티/덱 변경과 자동 저장을 호출한다. 기존 포획·성장·69전투·희귀 조건·저장 형식을 바꾸지 않았다.

## 이전 핵심 유물 검증 기록

[핵심 유물 5종](core-relics.md)을 추가했다. 관장 승리 후 시드 고정 세 후보에서 원정당 하나를 선택하고 교대·에이스·상태·보호막·소진 도구 운영의 효과와 대가를 적용한다. 일반 유물 10종은 계속 함께 모을 수 있다. 아직 선택하지 않았다면 다음 관장에 다시 기회를 받으며, 마지막 관장에서도 넘기면 핵심 없이 리그로 진행한다. 기존 보상·진행 중 전투를 재추첨하거나 저장을 초기화하지 않는다.

핵심 규칙 357개 검사로 발동 제한·대가·카드 미리보기/실제 수치·할인 대상 고정·강제 교대·기존 효과 조합·저장/복원·중복 보유와 이전 보상 보존을 확인했다. 세 별도 Godot 프로세스로 실제 첫 관장 보상 → 선택/다음 전투 행동 → 이어하기/승리/중복 정산 방지를 확인했다. 실제 X11 UI 39개 검사·클릭 7회·휠로 세 창 비율의 선택, 핵심 우선 표시와 11개 유물 메뉴의 끝 접근·버튼 겹침 방지를 확인했고 1920×1080 화면을 검토했다.

[현재 비교 측정](measurements/campaign-core-relics.md)은 관동 파티·10시드·여섯 보상 정책·두 야영지 운영의 120개 원정이다. 정상 완주 114개는 핵심 다섯 종류에 따라 최종 유물 구성이 나뉘었다. 이전 같은 조건의 관동 완주 115개는 모두 같은 10종을 모았다. 일반 유물의 수렴은 남아 있고, 핵심 효과만으로 모든 조합의 난도와 재미가 확정된 것은 아니다. 12개를 별도 프로세스에서 재측정해 모든 필드가 일치했다. 보고서 검사 10개도 통과했다.

기존 공유 덱 632개·조합 610개·능력치 55개·저장 1,771개·파일 복구 23개·이전 저장 능력치 호환 390개·연출 26개·덱 UI 33개·조합 UI 14개를 통과했다. 고정 시드 0/42/2026은 69전투를 완주하고 덱 원정 194개 검사를 통과했다. 30시드 원정은 29개 완주·1개 실제 전멸로 23,768개 검사를 통과했다. Linux/Godot 4.7.2 기준이며 다른 파티·초반 포획/영입·수동 밸런스·Windows 검증은 남아 있다.

## 이전 강화 비교·400개 원정 측정 기록

[야영지 카드 강화 비교](camp-upgrade-preview.md)를 추가했다. 카드 선택 후 현재/강화 후 카드 얼굴·비용·효과와 소유 포켓몬을 비교하고 확정한다. 취소와 Esc는 자원을 바꾸지 않고 카드 목록으로 돌아간다. 확정만 기존 강화 행동과 자동 저장을 호출하며 휴식·조사와 주 행동을 공유한다. 실제 X11 27개 검사·포인터 21회·Esc 세 번과 세 창 비율, 1920×1080 화면 검토를 통과했다. 덱 UI 33개·상인 UI 27개·야영지 UI 48개도 통과했다.

[현재 능력치 측정](measurements/campaign-species-level.md)을 10개 시드·400개 원정으로 갱신했다. 15개 파티와 관동 파티의 다섯 보상 주제를 휴식/육성 두 운영으로 비교한다. 육성 정책은 실제 재료 구매·사용·강화·유료 제거와 회복·친밀도를 사용하며 경제 항목을 나눠 기록한다. 기존 공식의 60개 표본과 분리하고, 양쪽 모두 완주한 같은 시드 쌍을 따로 비교한다.

관동 기본은 두 운영 모두 10/10 완주, 평균 283.3→255.7턴이다. 벌레는 0→2/10, 고스트는 2→4/10 완주했으나 성도 기본은 9→8/10으로 줄었다. 휴식 포기의 비용과 정책 편향이 있으므로 육성을 항상 우월한 선택으로 해석하지 않는다. 아기·물 보조형·단독 편성은 이번 영입 없는 정책에서 모두 완주하지 못했다. 관동 완주 115개의 최종 유물은 10종으로 같아졌으며 조합 수렴은 계속 보강할 지점이다.

모든 400개가 정상 완주/전멸로 끝났고 집계가 유효했다. 별도 프로세스 12개 원정을 재측정해 모든 필드가 일치했으며 새 도구의 휴식 운영은 도구 확장 전 새 능력치로 실행한 기존 정책 60개 결과를 그대로 유지했다. 측정 정책 21개·보고서 9개 검사와 잘못된 CLI 선택 5개를 통과했다. 피츄·삐·푸푸린의 시드 5 관장전이 116턴에 정상 종료됨을 확인해 모든 측정에 200턴 안전 제한을 명시했다. 기본 한도 100턴과 원정 15,000행동 제한은 유지하고 미완료는 보고서에서 거부한다. 종족값·카드 수치·적 레벨·희귀 조건과 저장 형식은 이번 작업에서 바꾸지 않았다. 사람의 승률·수동 밸런스·Windows 검증은 별도다.

## 이전 개체값·노력치 제거 검증 기록

개체값·노력치를 제거하고 아군·적의 여섯 능력치를 종족값·레벨만으로 계산한다. 카드·상태의 전투 보정은 유지한다. 배루키는 능력치 훈련 대신 야영지에서 세 진화 중 하나를 선택하고 다음 Lv.20 이상 레벨업에 자동 진화한다. 기존 v3 저장은 잃은 HP·기절·카드·자원·난수·진행을 보존해 변환하며 예전 배루키 준비도 진화 선택으로 이어진다. 현재 턴 에너지를 다시 주거나 포획·승리 보상을 중복 정산하지 않는다.

능력치 55개·성장 42,937개·특수 진화 302개·이전 실제 저장 호환성 390개·출발 덱 6,963개·연출 26개 검사를 통과했다. 기존 60개 밸런스 측정은 이전 능력치 규칙의 기록으로 표시했으며 이번 공식의 난도 근거로 사용하지 않는다. 실제 X11 UI 53개 검사(포인터 48회·키 9회), 세 창 비율·1920×1080 진화 선택 화면을 확인했다. 여섯 별도 Godot 프로세스의 준비·경험치 진화·재실행·추가 합류를 통과했다. 전체 저장 1,771개·파일 복구 23개·희귀 조우 1,329개·적 전술 6,993개·보스 전술 6,338개도 통과했다. 기본 정책 30시드는 29개 완주·1개 실제 전멸로 23,770개 검사를 통과했고, 고정 시드 0/42/2026의 덱 원정 194개 검사도 모두 69전투를 완주했다. 이는 자동 정책 결과이며 Windows와 파티별 수동 밸런스 검증은 남아 있다.

## 이전 출발 덱·측정 검증 기록

[스타팅·빌드 원정 측정](balance-measurements.md)을 추가하고 [60개 결과와 원본](measurements/campaign-balance.md)을 보관했다. 15개 파티 × 세 시드의 기존 정책과 관동 파티의 다섯 보상/상점 선호를 비교한다. 기본/희귀 포함 편성은 완주했으나 아기·보조형·단독 편성은 초반 관장 부근에서 자주 전멸했다. 포획·재료·강화/제거를 사용하지 않는 정책의 작은 표본이며 수동 승률이나 전체 종의 균형을 뜻하지 않는다. 두 측정을 재실행해 동일한 결과를 확인하고 미완료·중복·서로 다른 규칙/코드 지문의 보고서를 거부한다. 관동 파티의 18개 측정은 최종 유물 10종의 구성이 같아졌으므로 유물 우선 정책과 콘텐츠 풀의 수렴 양상도 다음 조정에서 검토한다.

미진화 스타팅 202종의 규칙 6,963개, 실제 X11 UI 36개 검사(포인터 29회·키 7회)를 통과했다. 세 창 비율·휠·소유자 필터·모달 차단·취소·실제 출발과 자동 저장을 확인하고 1920×1080 화면을 검토했다. 시작 규칙 34개·시작 UI 25개·저장 1,831개·연출 26개를 통과했다. 고정 시드 0/42/2026의 기존 원정도 각각 69전투·엔딩과 검사 194개를 통과했다. Windows 배포·더 많은 시드·파티별 수동 밸런스는 남아 있다.

기존 경로·경험치와 69전투·68야영지를 유지하고 선택 필드로 이전 v3 저장을 지원한다. 21종 규칙 1,329개, 전체 저장 1,831개·야영지 27,537개·특수 진화 302개·기록 100개·연출 26개 회귀 검사를 통과했다. 고정 시드 0/42/2026은 각각 69전투와 통합 검사 194개를 통과했다. UI 입력 69전투·엔딩 검사 2,673개도 통과했다. 세 등급 각각의 조사 → 예약/전투 → 포획 → 합류 선택/다음 캠프 → 전멸 → 다음 원정 스타팅을 18개의 별도 Godot 프로세스로 확인했다. 실제 X11 입력으로 세 창 비율·세 등급 조건/비용·조사/예약·포획/풀어주기와 자동 저장을 확인했고 1920×1080 화면을 검토했다. UI 검사 47개(포인터 27회·키 11회)를 통과했다. 별도로 프리져(시드 24)·뮤(16)·뮤츠(14)는 처음부터 자원을 직접 바꾸지 않는 카드 행동으로 포획하고 각각 69전투·엔딩까지 완주했다(30개 검사). UI·프로세스의 HP 경계 테스트와 실제 전체 자동 원정 검사를 구분하며 장시간 수동 밸런스·Windows 검증은 남아 있다.

[친밀도·시간대 진화](friendship.md) 9개 경로를 실제 경험치 레벨업과 연결했다. 초기 친밀도 70, 생존 승리 +8·기절 -10·생존 레벨업 +2·주 행동 휴식 +5를 적용하며 220 이상으로 레벨업하면 자동 진화한다. 야영지의 낮/밤 버튼으로 이브이의 에브이/블래키 분기를 준비하고 파티 목록·툴팁에서 진행을 확인한다. 시간 선택은 친밀도·HP·휴식 횟수를 바꾸지 않는다. 친밀도·시간은 선택 필드로 저장해 이전 v3를 그대로 복원한다.

신규 규칙 132개와 실제 X11 UI 32개 검사(포인터 19회·키 2회)를 통과했다. 세 창 비율의 시간 선택, 휴식 중복 차단, 실제 카드 전투 후 블래키·피카츄·마릴 자동 진화와 기술 선택·보상·자동 저장을 확인했다. 1920×1080 야영지·성장 요약 화면을 검토했고, 별도 Godot 프로세스 세 개로 준비 후 종료 → 이어하기와 실제 전투/진화 → 다시 종료 후 다음 야영지를 확인했다.

성장 42,937개·야영지 27,537개·돌/통신 진화 623개·전체 저장 1,831개·원정 기록 100개 회귀 검사를 통과했다. 기존 다섯 프로세스의 저장/구매/백업 복구와 세 프로세스의 재료 진화도 통과했다. 고정 시드 0/42/2026은 각각 69전투와 통합 검사 194개를 통과했고 UI 입력으로도 69전투·엔딩과 검사 2,673개를 통과했다. 수동 파티별 밸런스와 Windows 검증은 남아 있다.

## 이전 돌·통신 진화 검증 기록

[돌·통신 진화](evolution-items.md) 33개 경로와 재료 13종을 구현했다. 새 상인은 파티에 맞는 재료 하나를 판매하고, 가방 팝업은 현재/진화 후 모습과 이후 기술표를 안내한다. 진화 결과를 별도로 표시하고 레벨·경험치·기술·카드 강화·장비를 보존한다. 잔량·대상·장소를 검증해 중복 소비를 막으며 원정 기록과 자동 저장에 반영한다. 기존에 방문한 상인의 진열과 전체 경로는 그대로 보존한다.

진화 규칙 623개, 실제 X11 UI 29개 검사(마우스 19회와 Esc)를 통과했다. 세 창 비율에서 스크롤·취소·대상과 분기 선택·모달 차단·자동 저장을 확인하고 1920×1080 화면을 검토했다. 별도 Godot 프로세스 세 개에서 재료 구매 후 종료 → 재실행과 진화 → 다시 종료 후 다음 전투를 확인했다. 기존 저장·구매·백업 복구의 다섯 프로세스 검사도 통과했다.

성장 42,937개·야영지 27,537개·상점 규칙 1,199개·전체 저장 1,831개·기록 100개·연출 26개 회귀 검사를 통과했다. 고정 시드 0/42/2026은 각각 69전투를 완주하고 통합 검사 194개를 통과했다. 실제 UI 입력 경로로 69전투와 엔딩까지 이어지며 검사 2,673개를 통과했다. 현재 검증은 Linux Godot 4.7.2이며 파티별 수동 밸런스와 Windows 배포 검증은 남아 있다.


## 이전 보스 전술 검증 기록

[보스 전술](boss-tactics.md)을 관장 18명·사천왕 후보 31명·챔피언 후보 11명에 연결했다. 규리의 방어/특방 장벽, 독수의 독, 민화의 씨앗과 회복, 철구의 강화와 연타처럼 파티마다 아홉 가지 공통 유형을 다르게 배치했다. 별도 HUD를 늘리지 않고 기존 의도·상대 파티·지도 툴팁에서 공개한다. 연타는 공격/피해를 두 번 나누어 표시하며 첫 타격 기절 시 중단한다. 방벽은 능력치 단계와 보호막, 씨앗은 피해와 시전자 회복을 따로 재생한다.

보스 규칙 6,338개와 실제 X11 보스 UI 검사 35개(마우스 14회)를 통과했다. 연타의 시간별 HP와 공격 모션, 물리/특수 우회·치료 카드·실제 회복 예고·지도 전술을 확인하고 1920×1080 화면을 검토했다. 전투 정의와 순환 위치를 복원하며 진행 중인 이전 저장은 다음 보스전부터 새 전술을 사용한다. 별도 Godot 프로세스 다섯 개의 전투·야영지 저장/재실행·구매·백업 복구 검사도 통과했다.

고정 시드 0/42/2026은 카드 구매·보상·장비·저장 복원까지 포함해 각각 69전투를 완주했고 통합 검사 194개를 통과했다. 30개 시드의 자동 정책은 29회 완주·1회 전멸, 전체 원정 검사 23,769개를 통과했다. 실제 UI 입력 경로로도 69전투와 엔딩을 완주하며 검사 2,673개(포인터 2,164회·키 391회)를 통과했다. 일반 적 규칙 6,993개·전체 저장 1,831개·카드 전투 660개·원정 기록 100개·연출 26개 회귀 검사도 통과했다. 자동 완주는 모든 파티의 난도나 재미를 보장하지 않으며 수동 비교와 Windows 검증은 남아 있다.

기존 [원정 기록](run-records.md)과 상점·조합은 유지한다. 완료 원정 목록·플레이 시간·원인별 피해 기여도는 후속 범위다.
