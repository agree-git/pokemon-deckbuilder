# 원정 난도 비교 도구

개체값·노력치를 제거한 현재 능력치로 스타팅·보상 주제·야영지 운영·초반 영입을 비교한다. [초반 영입 159개 종료 결과](measurements/campaign-recruitment.md)와 [미완료 1개](measurements/campaign-recruitment-incomplete.json)를 분리해 보관한다. [핵심 유물 120개 결과](measurements/campaign-core-relics.md)와 [원본 JSON](measurements/campaign-core-relics.json)을 함께 보관한다. 핵심 도입 전 [400개 측정](measurements/campaign-species-level.md)과 이전 공식의 [60개 측정](measurements/campaign-balance.md)은 별도 기록이며 현재 결과와 합치지 않는다.

## 실행

Godot 4.7.2와 Python 표준 라이브러리만 사용한다. 게임용 저장과 분리할 때는 실행 명령의 `XDG_DATA_HOME`, `XDG_CONFIG_HOME`, `XDG_CACHE_HOME`에 측정 전용 임시 디렉터리를 지정한다. 도구는 원정을 세션에 채택하거나 저장하지 않는다.

```bash
# 15개 파티 × 10개 시드 × 두 야영지 운영
 godot --headless --path . --script res://tools/benchmark_campaign.gd -- --seeds 0,1,2,3,4,5,6,7,42,2026 --camps rest,develop --max-turns 200 --output /tmp/balance-starters.json
# 같은 관동 파티에서 보상/상점 선호 주제 5개 × 두 야영지 운영
 godot --headless --path . --script res://tools/benchmark_campaign.gd -- --seeds 0,1,2,3,4,5,6,7,42,2026 --parties kanto --styles relay,ace,status,shield,supply --camps rest,develop --max-turns 200 --output /tmp/balance-styles.json
# 다른 엔진/규칙/정책이나 중복·미완료 행을 섞지 않고 보고서 생성
 python3 tools/report_campaign_balance.py /tmp/balance-starters.json /tmp/balance-styles.json --json /tmp/balance.json --markdown /tmp/balance.md
# 정책과 보고서 검증
 godot --headless --path . --script res://tests/test_campaign_camp_policy.gd
 python3 tools/test_campaign_report.py
```

기본 옵션은 이전과 같은 시드 `0,42,2026`, 모든 파티, `baseline`, `rest`, 영입 없는 `off`다. `--styles`는 `baseline,relay,ace,status,shield,supply`, `--camps`는 `rest,develop`, `--recruitment`는 `off,early`를 받는다. 빈 선택·중복·알 수 없는 옵션·1000개를 넘는 측정은 거부한다. 출력 파일 작성 실패·불법 행동·지정한 턴/15,000행동 제한으로 중단된 원정·집계 오류는 실패 종료한다. 정상 전멸은 측정 결과이며 완주로 취급하지 않는다. `--max-turns` 기본값은 전투당 100턴, 허용 범위는 1~1000이다. 현재 10시드 측정은 모든 그룹에 200턴을 적용한다. 피츄·삐·푸푸린의 시드 5 첫 관장전이 116턴에 정상 종료됨을 확인해 긴 소모전의 제한을 명시적으로 늘렸다. 원정 행동 제한은 15,000이며, 제한에 걸린 원정을 패배나 완주로 바꾸지 않는다.

## 비교하는 선택

HP·레벨·경험치·골드·에너지·드로우·보상 난수를 직접 바꾸지 않고 실제 공개 행동으로 진행한다. 일반 전투와 레벨업 기술 선택은 기존 `CampaignPolicy`를 공유하며 `early`의 포획 시도 중에만 비치명 공격·방어·드로우 판단을 추가한다. `baseline`은 기존 보상 정책이며, 주제별 정책은 실제 제시된 보상과 상점에서 해당 주제의 카드·유물·지닌 물건을 우선한다. 선호 보상이 없으면 기존 선택을 따른다. 덱이 24장 미만이고 구매 후 100골드가 남을 때 주제 공용 카드 한 장을 구매한다. 이후 기술 학습으로 덱이 커질 수 있으므로 최종 덱 24장 제한은 아니다.

야영지 운영은 보상 주제와 독립된 비교 축이다.

| 운영 | 선택 |
|---|---|
| `rest` · 매번 휴식 | 기존 정책 유지. 휴식·장비·일반 회복약 사용. 주제별 운영에서만 만남을 해결하고 선호 카드를 구매한다. |
| `develop` · 육성·덱 관리 | 만남 해결, 지금 쓸 수 있는 진화 재료 구매·사용. HP 75% 미만·기절 또는 아직 친밀도를 올릴 진화 후보가 있으면 휴식, 그 외에는 카드 강화. 상인에게 저평가·중복 보조 기술 제거. |

육성 운영은 진화 재료·제거·주제 카드 구매 뒤 100골드를 남긴다. 필요한 일반 회복약은 이 예산보다 생존을 우선한다. 파랑포켓블록은 아름다움 170에 도달할 때까지만 실제 재고에서 구매·사용하고 다음 경험치 레벨업을 기다린다. 재료 분기가 여럿이면 현재 사용 가능한 첫 분기를 고르므로 원작 기술표를 고려한 최적 진화 시점을 찾는 정책은 아니다.

강화는 기존 기술 평가에 드로우·에너지·주제 적합도를 더해 고른다. 제거는 미강화 보조 기술의 낮은 평가나 중복을 기준으로 하며 공격·씨앗·회복 카드와 공용 카드는 남긴다. 마지막 소유 기술·최소 덱·상인당 1장 제한과 증가하는 비용은 실제 게임 규칙이 검증한다. 휴식과 강화를 함께 받거나 재고를 채우지 않는다. 이 정책은 게임의 자동 플레이 기능이나 플레이어에게 강요하는 추천 규칙이 아니다.

## 저장되는 측정값과 신뢰 범위

원정별 완주/전멸·마지막 장소/타입·승리 수·배지·턴·HP 피해·기절·교대·드로우·덱 크기·카드별 사용·유물·레벨을 남긴다. v2에는 능력치 기준 `stat_basis`, 행별 `camp_policy`, 핵심 선택이 있는 측정의 `core_relic`, 최종 종 목록, 실제 원정 경제 집계를 추가한다. 휴식·강화·제거·아이템 횟수와 카드/보급·진화 재료/제거/만남 지출을 나눠 비교한다. 오래 살아남은 그룹은 더 많은 골드와 야영지를 사용하므로 다른 완주 길이의 평균을 곧바로 효율로 해석하지 않는다. 별도의 동일 시드 비교 표는 양쪽 운영이 모두 완주한 원정만 묶어 턴·HP 피해를 비교한다. 한쪽의 초반 전멸을 빠른 완주로 계산하지 않는다.

측정 시간·무작위 원정 ID를 넣지 않아 같은 버전·시드·정책의 결과를 그대로 비교할 수 있다. 전투·원정·성장·적·보상·측정 정책과 데이터에서 SHA-256 지문을 만든다. 저장 호환 버전이 같아도 코드나 데이터가 다르면 보고서를 합치지 않는다. 보고서는 미완료·중복·엔진/버전/규칙/능력치 기준/정책/지문 불일치와 잘못된 경제 합계를 거부한다. 같은 파티·스타일·시드라도 야영지·영입 정책이 다르면 별도 표본으로 유지하며 야영지 비교에서도 영입 축을 섞지 않는다. v1은 단독으로 읽을 수 있다.

기본 `off`는 포획·영입을 하지 않는다. `early`는 첫 바이옴에서 최대 두 번 일반 포획을 시도하는 별도 축이다. 희귀 조사와 주제별 최적 전투 AI는 아직 넣지 않았다. 따라서 초반 탈락만으로 종족값·관장 레벨을 일괄 낮추지 않는다. 희귀 포함 파티는 이미 영구 해금한 계정의 반복 플레이를 가정한다. 결과는 정책의 비교이며 사람의 승률이나 전체 종의 균형을 뜻하지 않는다.

## 핵심 유물 도입 전 400개 표본에서 확인한 점

15개 파티 × 10시드 × 두 야영지 운영 300개와 관동 파티의 다섯 보상 주제 100개, 총 400개를 완료했다. 관동 기본 정책은 두 운영 모두 10/10 완주했고 같은 시드의 평균 턴은 283.3→255.7로 줄었다. 벌레는 0→2/10, 고스트는 2→4/10 완주했으나 성도 기본은 9→8/10으로 줄었다. 회복 대신 강화한 선택이 더 위험해지는 대진도 있다. 아기·물 보조형·단독 편성은 영입이 없는 이번 정책에서 완주하지 못했으며 다음에는 포획·영입을 함께 비교한다.

관동에서 완주한 115개 원정의 최종 유물은 모두 같은 10종이었다. 유물 우선 보상 정책과 콘텐츠 풀이 조합을 수렴시키는 문제는 계속 확인할 지점이다. 이번에는 [강화 전·후 비교 화면](camp-upgrade-preview.md)으로 야영지 선택의 효과를 먼저 명확히 표시했다.

규칙·자원을 직접 바꾸지 않는 정책 검사 21개, 보고서 검사 9개, 잘못된 CLI 입력 5개를 통과했다. 별도 프로세스에서 12개 측정을 반복해 모든 필드가 일치했다. 새 도구의 `rest`는 새 능력치로 도구 수정 전에 수행한 기존 정책 60개와 결과를 그대로 유지한다. 이는 측정 재현성 확인이며 수동 플레이나 Windows 검증을 대신하지 않는다.

## 핵심 유물 도입 후 120개 비교

관동 파티 × 시드 0~7/42/2026 × 기본·교대·에이스·상태·보호막·도구 보상 선호 × 휴식/육성 운영을 비교했다. 핵심 후보가 없으면 강제로 지급하지 않고 기존 보상 선택 정책을 따른다. 120개는 모두 정상 완주/전멸했으며 완주 114개에서 다섯 핵심과 다섯 최종 유물 구성을 확인했다. 일반 유물 10종은 여전히 완주 시 같은 풀로 수렴한다. 핵심 선택 분포·미획득·완주 구성 수를 보고서에서 확인할 수 있다.

```bash
godot --headless --path . --script res://tools/benchmark_campaign.gd -- --parties kanto --styles baseline,relay,ace,status,shield,supply --seeds 0,1,2,3,4,5,6,7,42,2026 --camps rest,develop --max-turns 200 --output /tmp/balance-core.json
python3 tools/report_campaign_balance.py /tmp/balance-core.json --json /tmp/balance-core-report.json --markdown /tmp/balance-core-report.md
```

핵심 도입 전후는 다른 규칙 지문이므로 파일을 합치지 않는다. 새 규칙의 시드 42·여섯 정책·두 야영지 운영 12개를 별도 프로세스에서 재실행해 모든 필드가 일치했다. 현재 정책은 핵심에 맞춘 최적 전투 AI를 추가하지 않았으며, 결과는 전술 효과·보상 선택이 달라진 첫 비교다. 초반 포획·영입과 다른 파티·수동 비교는 다음 범위다.

## 초반 영입 160개 실행: 종료 159개·미완료 1개

8개 편성 × 시드 `0,1,2,3,4,5,6,7,42,2026` × 영입 없음/초반 영입으로 실행했다. 보상은 기본 정책, 야영지는 육성·덱 관리, 전투 한도는 모두 200턴이다. [종료 결과 159개](measurements/campaign-recruitment.md)와 [JSON](measurements/campaign-recruitment.json), [한도 중단 원본 1개](measurements/campaign-recruitment-incomplete.json)를 보관한다. 한도에 걸린 원정을 패배·완주로 바꾸지 않는다. 160개 원본 실행은 미완료 때문에 종료 코드 1을 반환하며, 미완료를 포함하면 보고서도 거부한다. 분리된 종료 행만 보고서로 만들었다.

```bash
godot --headless --path . --script res://tools/benchmark_campaign.gd -- --parties kanto,bugs,babies,psychic,water,mixed,solo,solo_fish --seeds 0,1,2,3,4,5,6,7,42,2026 --styles baseline --camps develop --recruitment off,early --max-turns 200 --output /tmp/recruitment-all.json
# 아래 파일에는 정상 종료 159개만 들어 있다. 미완료 행을 합치면 실패한다.
python3 tools/report_campaign_balance.py docs/measurements/campaign-recruitment.json --json /tmp/recruitment-report.json --markdown /tmp/recruitment-report.md
```

`early`는 첫 지역 다섯 야생에서 볼·에너지·HP 25% 조건을 지켜 최대 두 번 포획한다. 같은 진화 계열은 피한다. 빈자리는 채우고, 가득 차면 현재 6능력치 합 + 최고 기술 평가의 3배가 가장 낮은 동료보다 15% 이상 높을 때 교체한다. 실제 정산 뒤 가치가 낮아지면 풀어주므로 포획 수와 영입 수를 구분한다. 야생 하나당 포획 준비를 세 턴 진행한 뒤 일반 전투로 돌아온다. 미래 진화·상성·덱 조합을 최적화하는 정책은 아니다. HP·기술·성장·보상을 직접 수정하지 않는다.

| 편성 | 영입 없음 완주 | 초반 영입 완주 | 포획 / 실제 합류 |
|---|---:|---:|---:|
| 관동 기본 | 10/10 | 10/10 | 2 / 0 |
| 벌레 | 1/10 | 1/10 | 0 / 0 |
| 아기 | 0/10 | 1/10 | 0 / 0 |
| 보조형 에스퍼 | 1/10 | 2/10 | 12 / 12 |
| 물 보조형 | 0/10 | 0/10 | 1 / 1 |
| 이브이·배루키·루브도 | 1/10 | 1/9 종료 + 1 미완료 | 8 / 8 (미완료 포함) |
| 이상해씨 단독 | 0/10 | 5/10 | 17 / 17 |

이상해씨 단독은 동료 영입으로 완주한 시드가 늘었으나 잉어킹 단독과 물 보조형은 여전히 완주하지 못했다. 포획을 노리는 카드 선택도 달라져 실제 영입이 없는 아기 편성의 결과도 바뀌었다. 그러므로 모든 차이를 영입 효과로 해석하지 않는다. 단독 잉어킹 시드 42는 6승에서 3승으로 줄었으며 포획 시도 자체의 생존 비용도 있다.
