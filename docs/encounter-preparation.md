# 다음 전투 준비

지도와 야영지의 **다음 전투 준비**를 누르면 다음 전투의 실제 상대 파티와 현재 덱의 상성을 확인한다. 야영지에서는 출발 전에 상점·가방·휴식·장비를 이용하고 다시 확인할 수 있다. 지도에서 다음 장소가 야영지이면 그 뒤의 전투를 보여 준다.

상단의 상대 스프라이트를 선택하면 그 포켓몬의 복합타입에 대한 카드 목록으로 바뀐다. 관장·사천왕·챔피언의 실제 파티 전원을 표시하며, 예약한 희귀 조우가 있으면 대체된 종·레벨·장소명을 사용한다. 조회만으로 희귀 도전을 예약하거나 단서를 조사하지 않는다.

| 탭 | 표시 기준 |
|---|---|
| 통하는 공격 | 현재 덱에 있고 살아 있는 동료가 사용할 수 있는 직접 공격. 카드 위에 상성 배율을 표시하며 약점 공략 사본 수도 안내한다. |
| 타격 무효 | 선택한 상대에게 직접 타격 배율이 0인 카드. 부가 상태 효과가 있다면 그 효과까지 막힌다는 뜻은 아니다. |
| 지속·조건부 | 화상·독·씨앗·혼란의 지속 피해, 보호막 전환, 상태 회수. 준비가 필요한 효과를 직접 공격 수에 합치지 않는다. |

실제 카드 얼굴·비용·효과·소유 포켓몬·강화를 표시한다. 같은 기술의 사본도 각각 한 장으로 센다. 카드가 많으면 가로 스크롤로 확인하며 한 카드가 직접 공격과 지속 효과를 함께 가지면 두 탭에 나타날 수 있다. 회복·방어·드로우만 있는 보조 카드는 피해 카드 목록에서 제외한다.

**배운 기술 목록이 아니라 실제 원정 덱**을 읽는다. 카드를 제거했다면 기술을 기억하고 있어도 공격 수단으로 표시하지 않는다. 기절한 동료의 기술은 제외하고 회복 안내를 표시한다. 공용 카드는 살아 있는 동료가 있으면 집계하며 모두 기절했다면 휴식·가방 회복을 안내한다.

## 계산 범위

정식 원정의 현대 복합타입 상성표를 그대로 사용한다. 예를 들어 물 → 꼬마돌은 ×4, 노말 → 고스트는 타격 무효이며 발버둥은 전투 규칙처럼 중립 ×1이다. 개발용 짧은 원정은 그 모드의 기존 단일 타입 상성을 유지한다.

이는 **상성에 따른 덱 구성 확인**이다. 실제 피해량·처치 턴·승률을 예측하지 않는다. 손패 순서·에너지·현재 공격 강화·능력치 단계·보호막·지속 작전·유물 할인·상대 행동에 따라 사용할 수 있는 카드와 피해는 달라진다. 보호막 전환에는 보호막, 상태 회수에는 적에게 적용된 상태가 필요하다. 현재 전투에서 지속 피해는 직접 타격 상성과 별도로 적용하므로 원작의 모든 상태 면역을 가정하지 않는다.

직접 공격이 없으면 피해 카드 부재 또는 지속·조건부 확인 안내를 표시한다. 출발을 막거나 플레이어 대신 덱을 바꾸지 않는다. 상점 구매·휴식·아이템·학습 후 다시 열면 변경된 실제 덱과 생존 상태를 읽는다.

## 저장과 검증

준비 창의 선택 상대·탭은 UI 상태다. 열기·탭 변경·상대 선택·닫기·Esc는 HP·경험치·볼·골드·덱·고유 ID·난수·경로·현재 전투·보상·저장 데이터를 바꾸지 않는다. 진행 중인 이전 v3 저장에서도 같은 원정을 조회하며 새로운 저장 필드를 요구하지 않는다.

Godot 4.7.2 기준:

```bash
godot --headless --path . --editor --import --quit
godot --headless --path . --script res://tests/test_encounter_preparation.gd
godot --headless --path . --script res://tests/test_encounter_preparation_ui.gd
# DISPLAY와 XTest가 있는 환경
python3 tools/test_native_pointer.py --probe native_encounter_preparation_probe
```

규칙 검사는 복합 상성·무효·발버둥·실제 공격 계산과의 일치, 지속/조건부 분리·강화·기절·공용 카드·배웠지만 덱에 없는 기술, 실제 보스 파티·희귀 예약과 조회 불변성을 확인한다. UI 검사는 지도/야영지·세 창 비율의 위/중간/아래 클릭, 마지막 상대 선택·탭·스크롤·모달 차단·닫기·Esc·자동 저장 보존과 실제 휴식 후 재집계를 다룬다. 긴 덱·조건부 카드·기절과 장소 위치는 명시적인 UI 테스트 상태이며 그 편성으로 그 장소까지 수동 공략했다는 뜻은 아니다.
