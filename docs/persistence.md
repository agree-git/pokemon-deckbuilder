# 원정 자동 저장과 이어하기

일반 원정은 **성공한 행동 직후 자동 저장**한다. 게임을 종료하고 다시 실행하면 시작 화면의 `이어하기`로 마지막 상태에 돌아온다. 새 원정 편성을 확정하거나 원정을 다시 시작하면 저장 슬롯을 새 도전으로 교체한다. 포획 도감은 별도 파일에 계속 유지한다.

## 저장 범위

- 원정 시드·대진·현재 장소·배지·사천왕 진행도·전투 정산 여부.
- 파티·포획 합류 대기·HP·기절·경험치·레벨·진화·배운 기술·기술 교체 대기.
- 트레이너 덱·부상 카드·손패·뽑을 더미의 순서·버린 더미·소진 더미와 카드 ID.
- 전투 턴·에너지·출전 멤버·적 파티·상태·카드 소유권·강화·보존·소진·지속 작전·유물 발동·지닌 물건·지연된 강제 교체·난수 상태.
- 골드·아이템·볼·보상 후보·전리품·야영지의 휴식 여부·이벤트 선택·상인 재고.

승리 결과에서 아직 정산하지 않았으면 이어서 한 번만 정산한다. 이미 받은 경험치·배지·보상과 처리한 야영지 선택은 다시 지급하지 않는다. 같은 카드·포켓몬을 가리키는 여러 참조도 복원해 전투와 원정의 파티·가방 상태가 따로 어긋나지 않게 한다.

이동과 카드·기술 애니메이션은 저장하지 않는다. 이동 중 종료하면 도착한 장소로, 전투 연출 중 종료하면 처리된 행동 이후 상태로 돌아온다. 메뉴·더미 확인창·검색 조건·야영지의 열린 탭도 다시 선택한다.

## 상태 표시와 복구

원정 상단의 `자동 저장됨`은 마지막 행동이 저장됐다는 뜻이다. 저장에 문제가 있으면 `저장 안내 · 다시 저장`으로 바뀌며 툴팁에 원인을 표시한다. 버튼을 눌러 현재 상태 저장을 다시 시도할 수 있다. 저장 실패가 현재 플레이의 파티나 경로를 초기화하지는 않는다.

주 파일을 읽지 못하면 같은 도전의 마지막 유효 백업을 불러오고 복구 안내를 표시한다. 이때 마지막 행동 일부가 이전 자동 저장으로 돌아갈 수 있다. 새 도전 이전의 백업이나 이미 패배·완료한 원정은 이어하기로 되살리지 않는다. 유효한 저장이 없거나 데이터·규칙 버전이 맞지 않으면 이어하기를 제공하지 않고 파일을 유지한 채 안내한다.

포획 기록은 원정 안에도 보관하고 영구 도감에 추가만 한다. 저장 사이에 종료되더라도 복원한 원정의 포획 기록을 도감과 다시 맞추며, 기존 해금을 취소하거나 중복 항목을 만들지 않는다.

## 파일과 구현

일반 원정 슬롯은 `user://journey.json`, 백업은 `.bak`, 도전 ID·종료 표식은 `.head`다. 포획 도감은 기존 `user://collection.json`을 사용한다. 저장 파일은 실행 환경의 Godot 사용자 데이터 폴더에 있으며 저장소에 포함하지 않는다.

`JourneySnapshot`이 명시적인 값과 UID 참조로 객체 그래프를 변환·검증한다. `JourneySave`는 객체 생성을 허용하지 않는 Variant 인코딩을 Base64/체크섬으로 감싸 저장한다. 64비트 시드·난수 상태와 정수 사전 키를 보존하며 임의의 리소스나 노드를 로드하지 않는다. 임시 파일을 쓰고 flush한 뒤 이름을 교체하며, 유효한 이전 체크포인트만 백업한다. 종료 표식은 종료 체크포인트보다 먼저 기록해 이전 백업이 패배를 되돌리지 않게 한다.

향후 경로는 시드와 규칙으로 재생성하고 서명을 비교한다. 바이옴 출현표 전체를 매번 복사해 쓰지 않는다. 데이터 지문과 `RULESET`, 파일 `VERSION`이 호환 조건이다. 저장 형식을 바꾸면 VERSION을, 전투·성장·경로 규칙을 바꾸면 RULESET을 올리거나 명시적인 마이그레이션을 작성한다. 호환되지 않는 이전 슬롯을 새 규칙으로 조용히 재추첨하지 않는다.

`TacticalBattle`과 `TacticalJourney`는 성공한 공개 행동이 끝났을 때 변경 신호를 보내며 `BattleSession`이 이를 저장한다. 포획은 볼 차감·합류 대기·포획 기록까지 완료된 뒤 한 번 알린다. 개발용 짧은 원정은 디스크 저장 대상에서 제외한다.

## 진화 재료 업데이트의 호환 처리

[돌·통신 진화](evolution-items.md)의 재료 가방과 선택적 야영지 `evolution_offer`도 v3에서 복원한다. 현재 종·기술·카드 UID·강화·장비를 그대로 보존하고 이미 소비한 재료나 매진 재고를 되돌리지 않는다. 이전 저장의 방문 상인은 원래 진열을 유지하며 새로 방문한 상인부터 진화 재료를 추가한다. 알 수 없는 재료·잘못된 재고 수량은 거부한다.

## 적 전술 업데이트의 호환 처리

적 역할 추가는 기존 v3 전투 정의·행동 배열·현재 순환 위치를 그대로 복원하는 호환 정책을 사용한다. 역할 필드가 없는 전투는 기본형으로 표시하며 현재 대진·기술을 재추첨하지 않는다. 새로 진입하는 전투부터 새 전술 생성기를 사용한다. 저장 형식·능력치·경험치·경로는 유지하므로 이번 변경으로 새 원정을 요구하지 않는다. [전술 규칙](enemy-tactics.md)을 참고한다.

[보스 전술](boss-tactics.md)도 같은 정책이다. 선택 필드 `boss`·`boss_style`과 연타 횟수·방벽 능력치·상태 종류를 검증하고 저장된 정의를 그대로 복원한다. 기존 진행 중인 보스전은 이전 패턴을 유지하고 다음 보스전부터 새 편성을 적용한다. 알 수 없는 인물·유형·능력치·상태나 잘못된 타격 횟수는 거부한다.

## 조합 콘텐츠 업데이트의 호환 처리

카드 6종·유물 3종 확장은 기존 v3 저장의 대진·덱·손패·보상 후보를 유지한다. 새 조건과 유물 발동 제한은 기존 불리언 `turn_flags`에, 소모전 작전은 `powers`의 허용 항목으로 저장한다. 기존 상태에 새 필수 필드를 추가하지 않는다. 확장 카드·유물은 새로 추첨하는 보상부터 등장하며, 이미 표시된 선택지를 바꾸지 않는다. [조합 규칙](build-synergies.md)을 참고한다.

## 상인 카드 진열 업데이트의 호환 처리

새로 방문하는 상인의 진열·할인·가격·매진 여부를 기존 야영지의 선택 필드 `card_offers`로 저장한다. 기존 v3의 방문한 상점에 이 필드가 없으면 보급품 진열을 그대로 유지한다. 불러오기와 재방문이 새 카드 진열을 만들거나 재고를 채우지 않는다. 구매한 기술 소유자가 나중에 파티를 떠나도 과거 진열 때문에 저장을 거부하지 않는다. 가격·종류·소유권 형식·할인·재고는 검증한다. [상인 규칙](merchant.md)을 참고한다.

## 원정 기록 업데이트의 호환 처리

전투·원정 `statistics`는 기존 필드 목록과 분리한 선택 필드다. 새 원정은 처음부터 기록하며, 필드 없는 v3 저장을 읽는 것만으로 과거 기록을 만들어 넣지 않는다. 성공한 기록 대상 행동 이후부터 부분 집계를 시작하고 화면에 범위를 알린다. 전투별 집계는 정산 시 한 번 원정에 합산하며 `_settled` 복원으로 중복을 막는다. 카운터의 범위·카드/유물 식별자·중복 장소와 전투 행/합계 일치를 검증한다. [집계 기준](run-records.md)을 참고한다.

## 검증

```bash
godot --headless --path . --script res://tests/test_journey_save.gd
godot --headless --path . --script res://tests/test_save_files.gd
python3 tools/test_save_process.py
# X11에서 실제 OS 포인터로 종료·재실행·이어하기·복구 확인
LIBGL_ALWAYS_SOFTWARE=1 python3 tools/test_save_process.py --native
```

객체 복원 검사는 69전투 전체와 기술 교체·중복 정산·강제 교체·부상·난수·야영지를 확인한다. 파일 검사는 손상·버전 불일치·잘못된 상태·백업의 도전 ID·종료 표식·포획 해금·저장 실패와 재시도를 검사한다. 프로세스 검사는 **전투 저장 → 새 프로세스에서 이어하기 → 야영지 저장 → 새 프로세스에서 재고·휴식 확인 → 파일 손상 후 복구**의 다섯 단계를 별도 Godot 실행으로 연결한다. 임시 XDG 사용자 폴더를 사용해 실제 플레이어의 저장을 덮어쓰지 않는다.

## 통합 덱 규칙 버전

규칙 식별자는 `campaign-69-unified-deck-v2`다. 이전 고정 기술·브레이크 원정 저장은 재개하지 않고 새 원정이 필요하다는 버전 불일치 안내를 표시한다. 기존 저장 파일을 읽는 것만으로 덮어쓰지 않는다. 별도 포획 도감과 스타팅 해금은 유지된다. 새 규칙의 보상 후보·장착 장비·캠프 강화/제거 사용 여부까지 저장한다.
