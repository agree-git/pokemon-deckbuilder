# 희귀 포켓몬의 단서와 첫 조우

main `07b0c41cda136e3cf0694be792e4ad169c0254e1`에 **21종·종별 장소/첫 조우·단서 95개**를 연결했다. 야영지 조사에서 새 단서를 읽고, 해당 장소로 이동한 뒤 짧은 첫 조우 문장을 보여준다. [실제 화면 12장·ZIP·21종/95단서 CSV](../review/rare-stories/README.md).

## 표시 흐름

- `data/rare_stories.json`의 종 ID별 `site`, `rumor`, `clues`, `arrival`, `backdrop_type`을 사용한다. 원작 대사를 인용하지 않은 프로젝트용 자체 문구다. 단서는 준전설 3개씩·환상 5개씩·초전설 7개씩 총 95개다.
- 조사 전에는 소문, 조사 후에는 **이미 획득한 마지막 단서**를 표시한다. 실제 `rare_hunt.clues` 길이로 결정하므로 보는 것만으로 다음 단서를 얻거나 미래 단서를 보여주지 않는다. 기존 저장도 같은 진척부터 표시한다.
- 각 조사 성공 시 새 단서가 팝업과 야영지 알림에 반영된다. 단서 기록 전체를 별도 목록으로 펼치는 기능은 이번 범위가 아니다.
- 이동 화면은 종별 장소 이름과 소문을 보여주고 장소 분위기에 맞는 **기존 바이옴 배경**을 사용한다. 첫 전투의 상단 장소명과 배경도 같은 선택을 따른다. 프리져는 설원, 뮤는 숲, 뮤츠는 강철 시설이다. 새로운 전용 유적 그림을 만든 것은 아니다.
- 첫 조우 문장은 0.2초 등장·2.2초 유지·0.2초 퇴장하며 기존 1/1.5/2배 연출 속도를 따른다. 해당 포켓몬의 울음소리와 함께 표시하고 완료 전에는 카드·교대·턴 종료·포획 입력이 잠긴다.
- 같은 전투 인스턴스의 UI 새로고침과 이미 행동한 중간 저장 복원에서는 첫 조우를 반복하지 않는다. 기존 트레이너 도입과 마찬가지로 **첫 행동 전** 저장을 파일에서 새로 복원하면 다시 표시할 수 있다. 이를 새 저장 필드로 바꾸지는 않았다.

## 규칙과 저장

`RareEncounterStory`는 읽기 전용 조회이며 반환 데이터는 깊은 복사다. 선택은 종 ID와 이미 얻은 단서 수로만 결정하고 난수를 사용하지 않는다. 배경 선택도 기존 바이옴 프리셋의 복사이며 이름만 해당 장소로 표시한다. 원정의 실제 바이옴·기상·전투 스탯을 바꾸지 않는다.

`RareEncounter`·`TacticalJourney`·저장 모듈은 수정하지 않았다. 대상 추첨, 3/5/7 배지·단서, 조사 비용, 원정당 한 번의 도전, 포획 HP/볼/에너지, 레벨·경험치·보상·69전투 경로는 유지한다. 전투의 `rare_intro_seen`은 기존 트레이너 도입처럼 표시용 메타데이터다. 영구 저장/난수 필드가 아니다. 사용자 전장 좌표 SHA는 `b0f2e796afbb02eb04bef728ae28cfd113b1b8a8d6939911d5d0371ba89724f3`이며 새 배경도 해당 프리셋의 보정 좌표를 사용한다.

## 검증

Godot **4.7.2/Linux** import 통과. 콘텐츠/UI **741개**, 기존 희귀 규칙 **1,329개**, 저장 **1,759개**, 실제 X11 **78개/18마우스 클릭/세 속도** 통과. 최종 로그에 스크립트 오류·잔여 리소스 경고가 없다.

- 21종 전체의 단서 개수·문구·새 단서/미래 단서 경계·깊은 복사·실제 한국어 글꼴/줄바꿈·UI 안전 영역·배경과 보정 좌표·조회/닫기 후 상태/난수·저장 복원을 확인했다.
- 실제 클릭으로 프리져(시드24)·뮤(16)·뮤츠(14)의 조사→새 단서→희귀전 예약→이동→첫 조우→자연 종료→카드 사용 후 저장/복원을 확인했다. 움직이는 실제 창을 촬영하고 대표 팝업·이동·첫 조우 화면을 직접 열어 보았다.
- 이 검사는 중간 진행 상태를 구성한 경계 fixture다. 앞선 전투를 모두 플레이하거나 새로 69전투를 완주한 자료가 아니다. Windows·수동 재미/밸런스·오디오 청감 검증은 이번 결과가 아니다.
- 초기 UI 검사 종료의 리소스 정리 경고는 테스트 종료 전에 대기 중인 UI 삭제를 처리해 해소했다. 초기 X11 검사에서는 클릭 처리 전에 다음 단계를 조회해 실패했으며 UI 처리 완료를 기다리도록 프로브를 고친 뒤 최종 실제 클릭 검사를 통과했다.

## 최신 main에서 재현

자료 브랜치의 게임 사본은 정리 전 기준이다. **최신 main**에서 검증 파일만 외부 폴더로 추출해 실행한다. `rare_test_support.gd`는 기존 경계 fixture이며 새 테스트는 같은 폴더의 상대 경로로 읽는다.

```bash
mkdir -p /tmp/rare-story-checks
for filename in rare_test_support.gd test_rare_stories.gd native_rare_stories_probe.gd; do
  git show development-materials:tests/$filename > /tmp/rare-story-checks/$filename
done
git show development-materials:tools/run_pointer_probe.py > /tmp/rare-story-checks/run_pointer_probe.py
godot --headless --path . --editor --import --quit
godot --headless --path . --script /tmp/rare-story-checks/test_rare_stories.gd
# 실제 X11/DISPLAY와 libXtst가 있는 환경에서만 실행:
python3 /tmp/rare-story-checks/run_pointer_probe.py --project-dir . --script /tmp/rare-story-checks/native_rare_stories_probe.gd
```

실제 창 검사끼리는 동시에 실행하지 않는다. 검증 프로세스가 끝났는지 확인하고 실패한 프로브가 남으면 해당 프로브만 종료한 뒤 다시 실행한다. 캡처는 `/tmp/pokemon-rare-stories`에 생성된다.
