# 원정 기록과 밸런스 확인

지도·야영지·보상·승리/패배 화면의 파티 아래 **원정 기록** 버튼으로 현재 도전의 집계와 선택을 확인한다. 평소 전투 HUD에 통계 숫자를 늘리지 않고 상세 창으로 제공한다. 완료한 원정 목록을 영구 보관하는 화면은 아직 없다.

## 표시하는 내용

상단에는 전투·생존·골드·덱 성장의 네 묶음을 표시한다. 상세 창은 세 탭이다.

- **전투별 기록:** 정산한 전투의 이름, 승패, 턴 수, 받은 HP 피해, 아군 기절 횟수. 최신 전투부터 표시하며 69전투 전체를 스크롤한다.
- **카드·골드 선택:** 카드/유물/지닌 물건 보상 선택 또는 넘김, 상점 카드 구매·가격, 강화, 제거·비용, 전술 수업. 카드와 장비 이름을 선택 당시 그대로 보관한다. 카드·보급품·제거·수업 지출을 나눠 표시한다.
- **카드 사용·유물 발동:** 정산한 전투의 카드별 사용 횟수와 유물별 발동 횟수. 카드 사본·소유자·강화 여부는 합산하고 횟수 내림차순으로 표시한다.

결과 화면에도 사용 카드와 받은 피해를 간단히 표시하며 상세 기록을 열 수 있다. 보고서 열기·탭 이동·닫기는 원정과 저장 상태를 바꾸지 않는다. 배경의 카드 구매·이동 입력은 모달이 막으며 Esc는 기록 창만 닫는다.

## 집계 기준

통계는 **성공한 규칙 처리에서만** 더한다. UI·연출·툴팁·드로우 순서 조회에서 집계하지 않는다. 잘못된 행동, 골드 부족, 매진 카드 재구매, 이미 사용한 휴식이나 보상은 세지 않는다.

| 항목 | 기준 |
|---|---|
| 카드 사용 | 실제 사용한 카드, 기술/도구/트레이너/상태를 구분. 보존·회수만으로 사용 횟수를 늘리지 않음 |
| 피해 | 실제 HP 손실. 과잉 피해는 남은 HP까지만. 포획은 공격 피해에 포함하지 않음 |
| 보호막 방어 | 아군 보호막이 실제 흡수한 수치. 부여했지만 쓰지 못한 보호막과 전환 소비는 제외 |
| 회복 | 최대 HP를 넘는 초과 회복을 제외한 실제 HP 증가. 전투 회복(씨앗 흡수 포함)과 야영지 회복/부활을 구분. 레벨 성장의 HP 증가는 회복으로 세지 않음 |
| 교대 | 기술 자동 교대·수동 교대·강제 교대를 별도 집계 |
| 에너지 | 카드·수동 교대·포획의 실제 비용. 환급이 있어도 사용한 비용은 유지. 미사용 에너지는 실제 턴 종료 직전의 잔여 합계이며 승리 턴에 남은 자원은 포함하지 않음 |
| 드로우·재섞기 | 실제 손으로 받은 카드와 비어 있는 드로우에 버린 더미를 재섞은 횟수. 손패 상한으로 받지 못한 카드, 회수한 카드는 드로우에서 제외 |
| 골드 수입 | 전투 보상·이벤트 판매 수입. 시작 골드 100은 제외 |
| 골드 지출 | 실제 결제한 카드 할인 가격·보급품·제거·수업 비용. 무료 보상·휴식·강화는 골드 지출이 아님 |
| 유물 | 실제 발동 지점의 횟수. 구급함은 전투당 한 번이며 자동 교대·상태·도구 발동 제한을 그대로 따름 |

유물 발동은 효과 설치/발동 수이며 **실제 피해 기여도·회복 기여도와 같지 않다**. 예를 들어 교대 배턴이 준비한 추가 피해를 쓰지 못할 수도 있고, 보급 벨트가 발동해도 손패가 가득 차면 드로우는 0이다. 사용 횟수 하나만으로 카드의 강도를 판단하지 않는다. 플레이 시간·빌드 자동 평가·원인별 피해 기여도는 아직 집계하지 않는다.

전투 중 수치는 전투 객체에 누적하고, 승리·포획·패배를 원정에서 정산할 때 한 번 합산한다. 도중 이어하기로 돌아와도 이미 처리한 행동이나 정산을 다시 더하지 않는다. 보고서는 정산한 전투를 기준으로 하며 향후 행동을 추정하지 않는다.

## 저장과 기존 원정

전투와 원정의 선택 필드 `statistics`에 카운터·카드/유물별 횟수·전투 행·카드 선택을 저장한다. 전투별 수치 사본은 정산 이후 변하지 않으며, 합계가 전투 행들과 일치하는지 저장 검사가 확인한다. 음수·잘못된 형식·알 수 없는 카드/유물·중복 장소 행을 거부한다.

v3 원정을 그대로 이어갈 수 있다. 필드가 없는 기존 저장은 로드 시 과거 수치를 만들어 넣지 않는다. 첫 기록 가능한 행동부터 집계를 시작하며 **업데이트 이후 기록만 집계**라고 표시한다. 이미 진행한 전투 도중 시작된 집계는 해당 행에 `*`를 붙인다. 기록 창을 읽거나 실패한 요청을 보내는 것만으로 집계를 시작하지 않는다. 새 원정은 기록을 새로 만든다.

데이터는 게임의 로컬 원정 저장에 포함한다. 외부 전송·자동 밸런스 변경은 없다. 완료/패배 원정은 기존처럼 이어하기 대상으로 되살리지 않으며, 현재 결과 화면에서 상세 기록을 확인한다.

## 검증

```bash
source /workspace/.cloud-setup/pokemon-deckbuilder/env.sh
godot --headless --path . --editor --import --quit
godot --headless --path . --script res://tests/test_run_statistics.gd
godot --headless --path . --script res://tests/test_run_report_ui.gd
godot --headless --path . --script res://tests/test_deck_run.gd
python3 tools/test_save_process.py
source /workspace/.cloud-setup/pokemon-deckbuilder/enable-display.sh
LIBGL_ALWAYS_SOFTWARE=1 python3 tools/test_native_pointer.py --probe native_run_report_probe
```

규칙 100개 검사로 실제 피해/방어/회복·포획·교대·유물 환급과 사용 비용 구분, 드로우·재섞기·중복 정산 방지, 보상/이벤트/상점/강화/제거 지출, 디스크 복원, 기존 저장의 부분 집계를 확인했다.

기록 UI는 검사 25개를 통과했다. 실제 X11 마우스 16회와 Escape 키로 세 창 비율, 탭의 위/중앙/아래 클릭, 배경 입력 차단과 닫기, 69전투 챔피언 결과·패배·이전 저장의 표시를 검사했다. 1920×1080 화면을 직접 확인했다. 저장/재실행/구매/백업 복구도 별도 프로세스 다섯 개로 검증했다.

고정 시드 0/42/2026은 상인 구매·보상·장비·저장 복원을 포함해 각각 69전투를 완주했다. 원정 통합 검사 194개는 69개 행의 유일성·합계, 카드 사용 합계, 구급함 69회와 `시작 100 + 수입 - 지출 = 최종 골드`를 확인한다. 전체 저장 1,807개, 기본 카드 전투 660개, 상점 규칙 1,199개와 연출 검사 26개도 통과했다. 이는 회귀 검증이며 모든 파티/빌드의 밸런스를 확정한 것은 아니다. 실행 검증은 Linux Godot 4.7.2 기준이다.
