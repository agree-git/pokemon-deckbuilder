# 배경별 포켓몬 접지 좌표

배경마다 그려진 발판 위치가 다른데 공통 화면 좌표에 포켓몬을 놓으면 발판 밖에 서게 된다. `data/battlefield_layouts.json`은 **바이옴 18·사천왕 룸 18·챔피언/공용 룸 12, 총 48개 셀**의 아군/적 접지점을 기록한다. 2026-10-16 사용자가 HTML에서 수정해 업로드한 파일을 소수점까지 그대로 적용했다. 26개 셀(아군 25·상대 23)이 달라졌으며 배경 PNG는 변경하지 않았다.

적용 JSON의 SHA-256은 `b0f2e796afbb02eb04bef728ae28cfd113b1b8a8d6939911d5d0371ba89724f3`이다. 촬영 manifest에도 이 해시를 기록하며 패키징 시 현재 파일과 일치하는지 검사한다.

## 좌표와 카메라

- 좌표는 1536×1024 아틀라스의 **해당 셀 내부 픽셀**이다. 셀 크기는 768×1024/3이며 왼쪽 위가 (0,0)이다. 실제 아틀라스 분할과 같은 소수 높이를 사용한다.
- `ally`, `enemy`는 발판 또는 비어 있는 바닥의 접지점을 **수동 지정한 값**이다. 현재는 사용자 HTML 수정 좌표를 기준으로 하며 자동 이미지 인식 결과가 아니다. 별도 발판이 없는 `champion_2`의 여섯 룸은 바닥의 앞/뒤 전투 위치를 지정한다.
- 화면 폭 / 셀 폭을 확대율 `s`로 삼고, 카메라 Y는 `floor(화면 높이 × 565/1080 − ally.y × s)`로 계산한다. 아군 발밑을 약 565px에 유지해 HP·보호막·손패 공간을 남긴다.
- 카메라를 내림하기 전에는 JSON 원본의 double 정밀도를 유지한다. 소수 좌표 297.6/287.2를 먼저 Vector2로 바꾸면 반올림 오차로 카메라가 1px 달라지는 문제를 막으며 HTML 미리보기와 같은 내림 규칙을 따른다.
- 실제 접지점은 **배경 원점 + 셀 내부 접지점 × s**다. `BattlefieldLayout.frame/project()`를 배경과 캐릭터가 함께 사용한다. 포켓몬의 키나 애니메이션이 카메라를 움직이지 않는다.
- 몸 중심의 연출 기준점은 접지점에서 위로 88px이다. 투명 여백을 제외한 스프라이트 하단 중앙을 접지점에 맞춘다. 교체 중 축소/확대에도 발밑이 이동하지 않는다.

1920×1080의 예:

| 배경 | 아군 셀 좌표 | 적 셀 좌표 | 아군 화면 좌표 | 적 화면 좌표 |
|---|---|---|---|---|
| 노말 바이옴 | (223.4,287.1) | (563.5,237.6) | (558.5,564.75) | (1408.75,441) |
| 격투 사천왕 | (147,268) | (596,218) | (367.5,565) | (1490,440) |
| 그린 챔피언 | (169,292) | (575,214) | (422.5,565) | (1437.5,370) |

스프라이트 위치를 픽셀에 맞추므로 실제 발끝 오차는 최대 약 0.71 화면 픽셀이다. 아군이 항상 아래, 적이 위이며 배경의 실제 발판 간격에 따라 높이 차이가 달라진다.

## HUD와 연출

HP 패널은 접지점 24px 아래, 보호막·상태 표시는 그 아래에 붙는다. 화면 가장자리/상대 파티 목록을 넘지 않도록 가로 위치를 제한한다. 행동 예고는 실제 적 스프라이트의 불투명 영역을 보고 머리 위 또는 옆에 배치한다.

스프라이트는 기본 4배다. 큰 종이 상단 안내 또는 양쪽 파티 목록과 겹칠 때만 3배/2배의 정수 배율을 선택한다. 크기를 줄여도 접지 좌표는 유지한다. 그림자·공격 이펙트·포켓볼 회수/출전도 같은 좌표를 따른다. 트레이너는 상대 접지점을 따라 서되 오른쪽 파티 목록 안으로 들어가지 않도록 제한하며 투척은 실제 손 위치에서 시작한다. 도입 중에는 상대 행동 예고를 숨겨 트레이너 얼굴을 가리지 않는다.

전투 규칙·난수·능력치·성장·저장 형식은 변경하지 않는다. 알 수 없는 외부/개발용 배경은 기존 공통 배치로 폴백한다.

## 조정과 확인

직접 배경을 보며 옮기려면 [독립 HTML 위치 수정 도구](battlefield-editor.md)를 사용한다. 배경 48종과 386종 앞뒤 스프라이트가 포함되어 있고 마우스/터치로 좌표를 지정한 뒤 게임 형식 JSON을 내려받을 수 있다. 도구의 최신 초기값도 적용한 사용자 JSON으로 갱신한다. 이번 적용은 사용자가 정한 위치를 반영하며 모든 종의 실제 발/꼬리/비행 자세를 개별 보정한 작업은 아니다.

1. 아틀라스의 해당 셀에 그려진 발판/바닥을 보고 JSON의 두 좌표를 수정한다. 원본을 바꾸면 좌표도 다시 검토한다.
2. `godot --headless --path . --script res://tests/test_battlefield_layout.gd`로 48개 배경·크고 작은 대표 종·투영·리사이즈·축소·UI 겹침·상태 불변을 확인한다.
3. [전체 배경 촬영](background-review.md)을 실행한다. 실제 전투 65장과 좌표 가이드 48장을 만든다. 갤러리의 **접지 좌표 보기**를 켜면 포켓몬/HUD를 숨기고 배경 위 기준점과 원본/화면 좌표를 볼 수 있다. `floor_coordinates.csv`에 배경 48종 전체의 수치를 저장한다.

자동 검사는 좌표 변환/겹침을 확인하며, 선택한 원본 좌표가 미술적으로 적합한지는 가이드와 실제 렌더링으로 검토한다. 실행 검증은 Linux/Godot 4.7.2이며 Windows 실행은 별도다.
