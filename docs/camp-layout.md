# 야영지 버튼·글자 겹침 수정

사용자는 팝업 중첩보다 **버튼/글자가 서로 겹치는 현상**이라고 명확히 답했다. 새 버전과 EXE는 수정이 끝난 뒤 사용자가 요청할 때만 만든다. 원정v28/효과19/게시 데이터·가격·아이템·저장·RNG와 배경 좌표는 그대로다.

## 원인과 수정 지도

- `scripts/ui/tactical_journey_ui.gd`: 모든 탭에 놓이던 연구 버튼이 y354의 장비 제목/상점 제목과 y382부터 시작하는 가방 영역을 침범했다. 버튼을 헤더(1435,130,305,58)로 이동하고 야영 화면 제목의 폭을 나눴다.
- 같은 파일의 `_gear`: 유물31개 fixture에서23개 버튼이 내용 하단 y870 이후로 내려갔다. `RelicScroll`의4열 그리드/클리핑과 세로 스크롤로 y774~864 안에서 표시하며 안내/출발 버튼 영역을 보존한다.
- `_shop`: 보급품·설명은 `ShopSupplyScroll`의 y390~866 안에서 스크롤한다. 품명/가격/재고와 오른쪽 구매 버튼에 각각 공간을 배정했다. 수량·가격·구매 로직은 수정하지 않았다.
- `scripts/ui/combat_widgets.gd`: 새 `fit_button`은 지정한 버튼만 적용한다. 최소14글자크기까지 맞추고 넘치는 글자는 말줄임/클리핑,전체 이름은 툴팁으로 표시한다. 모든 공통 버튼을 일괄 변경하지 않는다.
- `scripts/ui/pokedex_workshop.gd`: 동료/탭/교체할 기술 버튼에 위 도구 적용. `_input`에서Esc를 처리해 검색창이키를소비하기전에연구화면을닫고아래야영으로돌아간다. 캠프 밖으로 나가지 않는다.

## 실제 확인

- 수정 전 실제 배치 프로브에서 연구/장비 제목 사각형 교차와 유물31개 중23개가하단영역으로벗어남을확인했다. `/tmp/pokemon-camp-before.log`만 로컬에 둔다.
- `tests/native_camp_layout.gd`: Godot4.7.2/실제1920×1080 X11/XTest의 최종 **47검사/0실패·16 OS클릭**,휠과Esc를 함께 사용했다. 유물31개/지닌물건55개/많은가방물품/보급품5종/긴기술명4개를 가진 명시적 UI fixture다. 실제 원정에서 그 조합이 등장했다는 뜻은 아니다.
- 유물 마지막 행/가방/보급품 스크롤의 경계와 공통 버튼 분리,실제 장착·회복약·가격대로 구매,기술 훈련/TM 전환,검색창 초점에서Esc로닫기,강화 미리보기/취소/닫기를 확인했다. 마지막 탐색은 fixture의 HP/가방/골드/덱/경로/RNG를 바꾸지 않았고 별도 실제 자동저장 원정의 전체 스냅샷/RNG·저장 바이트는 동일했다.
- PNG5개(다량유물/상점아래/가격/긴기술명/TM)를 직접 확인했다. 최종 로그 SCRIPT ERROR/ERROR/리소스 누수 없음. 원정/아이템 보유량이 큰 것은 fixture로만 준비했다.
- 초기 검사에서 긴휠입력이 끝나기 전에 클릭하는 타이밍과 검사 변수형을 바로잡았다. 실제 검사에서 연구검색창Esc 문제를 발견해 수정한 뒤 관련 야영 탐색 묶음을 재확인했다. 중간 실패를 통과로 보고하지 않는다.
- 증거는 `/tmp/pokemon-camp-layout/`,최종로그 `/tmp/pokemon-camp-layout-native-done.log`다. 격리XDG 데이터/PNG/긴로그는 커밋하지 않는다. 해당 문제 확인만 수행했으며 전체919 효과/69전투/이전 전체창은 반복하지 않았다.

## 재현과 배포 상태

`source env.sh`,`source enable-display.sh` 뒤 격리XDG를 지정하고 `python3 .dev-materials/tools/native_pointer.py --project-dir . --script .dev-materials/tests/native_camp_layout.gd`를 실행한다. 한 디스플레이의 드라이버는 하나만 사용한다. 휠 입력은 XTest의 press/release 지연을 포함해 끝날 때까지 기다린다.

수정은 main에만 반영한다. 태그·게임 규칙 버전·Release 기본값은 갱신하지 않았고 빌드/export/Windows CI/EXE 생성은 실행하지 않았다. 기존 배포 v0.28.1은 그대로다. 사용자가 수정 마무리와 새 배포를 요청하면 그때 누적 변경으로 한 번 제작한다.
