# 기술 사용 시 포켓몬 동작

main `be66c80`. 사용자는 기술을 사용할 때 포켓몬이 너무 정적이라고 요청했다. 기존 Gen5 애니메이션 프레임 위에 준비→발동→복귀 자세를 더했다. 새로운 그림/기술 규칙/전투 지연은 추가하지 않는다. 새 버전·EXE·CI·Release는 재요청까지 보류한다.

## 필요한 코드 세 곳

- `scripts/ui/combat_motion.gd::use_move`: 표시용 기술 category와vfx.primary로 타격/베기/발사/충전/방어/회복/보조7계열을 고른다. 방향은 아군·상대에 맞춰 반전한다. 뒤로 움츠리기, 앞으로 내딛기/도약, 몸통 신축/기울기, 복귀를 총0.40초에 배치한다. 기존 `UiMotion.combat` 배속을 사용해 기술 이벤트의0.40초 대기를 늘리지 않는다.
- `scripts/ui/battle_canvas.gd`: 양쪽 `stretch`/`lean`을 표시한다. 스프라이트의 고정 opaque bounds 발 지점을 변환해 회전/신축 중에도 발을 기준으로 움직인다. 기본 배경/발 좌표/맞춤 줌은 유지한다. 그림자는 바닥에 남고 돌진의 가로 이동만 따라간다. 원본 아틀라스/프레임 시계/앞뒤 뷰도 유지한다.
- `scripts/ui/tactical_ui.gd::_play_event`: 유효한 기술이면 아군·상대·변화기 모두 `use_move`를 호출한다. 기존 상대`action=move`도 포함한다. 기존VFX/타격 플래시는 그대로다.

`hit`는 기존 피격 흔들림에 약한 반동 자세를 함께 쓰며, `hit_motion=false`면 기존처럼 둘 다 생략한다. 공격자 동작은 이 피격 설정과 별개로 유지된다. `settle_poses`는 전체 행동 종료 때 공격/피격 tween만 중단하고 양쪽 자세·화면 흔들림을0/1로 복귀시킨다. 소환·기절 factor/반짝임·효과는 초기화하지 않는다. `reset`은 기존처럼 전체 tween/소환·기절 factor도 복원한다.

게임의 피해·명중·턴·카드·전투 RNG·UID·저장/게시JSON/승인 파티는 바꾸지 않는다. 모션의 `last_profile`은 검사/표시용이며 게임 상태에 저장하지 않는다. 원본 [포켓몬 애니메이션](pokemon-animation.md)과 달리 이 작업은 기술 발동 시 전체 몸체의 연기다.

## 검사 범위와 실제 결과

Godot4.7.2 실제 X11 1920×1080/Dummy/격리된 XDG. 기존 `tools/native_pointer.py`로 다음 두 스크립트 중 관련 범위만 실행한다.

- `tests/native_combat_motion.gd`:7계열×아군·상대, 발 기준/정확한 복귀, 별도 속도1.5/2배, 중단·피격 설정·재시작, 전역 RNG/원정/실제 저장 보존, 실제Q 카드·Enter 상대턴 결과와 직접 계산한 기준 snapshot의 동일성을 묶는다.
- `tests/native_combat_motion_flow.gd`:위 스크립트를 상속해 실제Q/Enter의 자연 재생과 자세 종료만 좁혀 확인한다. 저프레임8fps/2배속, 종료 시 남은 양쪽 pose tween 중단, 기절 factor 보존, 뒤늦은 tween의 재오염 없음, 재시작 복원을 추가한다.
- 최초 실행은 검사 코드의 존재하지 않는 `Tween.get_speed_scale` 호출에서 중단됐다. 실제 동작을 일정 비율 시간에 직접 진행해 비교하도록 검사만 고쳤다.
- 보정한 묶음은 **65항목 중64통과/1실패**였다. 전계열·발 기준·배속/피격/스냅샷/실제 저장과 상대턴은 통과했지만, 자연 플레이어 종료의 자세/상태 결합 검사에서1개 실패했다. 일반 조건의 좁힌 재현4항목은 통과했다.
- 부모 이벤트 tween과 자식 자세 tween이 느린 프레임에서 인접 프레임에 끝날 수 있어 `_finished`에 `settle_poses`를 연결했다. 이후 **관련 구간만10검사/0실패**. 저프레임·2배속의 상태/RNG/자세 복귀와 기절 보존도 포함한다. 최종 전체65항목은 반복하지 않았다.
- 증거 `/tmp/pokemon-combat-motion/pose-{strike,cast,heal}.png`, 로그 `/tmp/pokemon-combat-motion-{native,recheck,flow,final}.log`. 타격 PNG와 녹화의 추출 프레임을 시각 확인했다. 최종 범위 로그 SCRIPT ERROR/ERROR/누수 없음. 기존 소프트웨어 VSync 안내만 있다.
- `MOTION_RECORD=1`은 선택적인14초 상한의 ffmpeg/X11 미리보기 녹화다. 게임 빌드/export가 아니다. 이번 MP4는 실제236프레임/1920×1080/약8.07초로 디코딩 확인했다. 앞부분7동작은 검사 fixture의 직접 연출, 뒤는 실제Q/Enter 입력이다. 녹화기에서X11 SHM 안내가1번 있었으나 영상은 생성됐다. 최종 좁힌 재검사에서는 녹화하지 않았다.
