# 악몽·멸망의노래·치유 인계 · 원정 v19

새 원정v19/플레이어 효과11에4개 기술을 보완해 누적423개다. 기존v1~v18 입력/전용 엔진은 동결한다. NPC 대진/기술은 바꾸지 않았으며 PP/부활 시스템은 추가하지 않았다.

| 기술 | 카드 각색 |
|---|---|
| 악몽171 |잠든 상대에게 매 상태 처리 최대HP¼ 피해(내림,최소1). 적용은 보호/대타/공중 회피에 차단되지만 설치된 지속 피해는 보호막/대타를 우회. 마지막 수면 처리까지 피해를 주고 기상에 해제. 시전자 교대는 유지,대상 교대/기절은 해제 |
| 멸망의노래195 |현재 사용자/상대에게 각각 카운트3. 상대 행동 후 날씨 처리까지 마치면1씩 감소하고0에 기절. 보호/대타/공중/타입 무효를 우회하는 전체 음파 효과. 재사용으로 남은 카운트를 연장하지 않으며 교대한 개체의 카운트만 해제 |
| 치유소원361 |사용자가 기절하고 다음 입장 피해를 견딘 동료의 HP/상태 회복. 살아 있는 다른 동료가 없으면 자원/교대/손패 변경 없이 거절. 사용 카드는 소진 |
| 초승달춤461 |같은 기절 후 회복 인계. 이 게임은 PP가 없어 PP 회복은 생략. 사용 카드는 소진 |

멸망의노래로 같은 순간 카운트가0이 된 양쪽을 모두 처리한 뒤 기존 승패/상대 입장/강제 교대를 판정한다. 양쪽 마지막 포켓몬이 동시에 기절하면 기존 아군 패배 우선 규칙을 유지한다. 다음 상대에게 이전 카운트를 넘기지 않는다. 카운트는 완료된 상대 행동 단계 기준이며 원작의 속도/턴 순서를 새로 만들지 않는다.

치유 인계는 입장 설치 피해 처리 뒤 살아 있는 첫 교대 동료에게 한 번 적용한다. 입장 피해로 기절하면 다음 교대까지 대기하며 부활시키지 않는다. HP 회복에는 기존 회복 감소 유물/회복봉인을 적용하고 상태는 해제한다. 회복봉인 중에도 인계는 소비한다. 두 기술의 PP 회복 차이 외의 핵심 특징을 동일한 카드 동작으로 살렸다.

## 코드와 저장 계약

- `scripts/tactics/player_move_fate.gd` / `data/player_move_fate_v19.json`;선택 `fate_context={nightmare,perish,wish}`. 대상UID별 악몽 표시/멸망 잔여1~3,대기 치유 기술ID(0/361/461). 새 문맥을 이전 원정에 주입하면 빈 값도 거절한다. 기존 선택 문맥은v19에서도 유지한다.
- 공통 `PlayerTechniques`의 정의/미리보기/거절/사용 후/교대 훅만 효과11로 확장한다. `TacticalBattle._tick`의 수면 감소 전 악몽,날씨 후 카운트,기절/포획 정리와 시작/종료 정리를 연결한다. 기존 피해 계산은 수정하지 않는다.
- 교대의 회복은 기존 보스/플레이어 입장 훅 뒤 처리한다. 강제 교대의 기존 `_pending` 분기를 사용하며 추가 상대 행동이나 턴을 생성하지 않는다. BattleFrame과 UI는 분리된 새 문맥을 사용한다.
- 생성기 `tools/import_player_move_fate.py --game-dir . --csv-dir /path/to/csv`는v18 기반 SHA와v10→v18 체인/고정CSV4종 SHA를 확인한다. 임시 보호막5를 제거하고 강화는 비용-1로 처리한다.

## 최소 검사와 다음 작업

`tools/check.py --suite player-fate`는 `tests/test_player_move_fate.gd` 한 스크립트다.4개 순수 미리보기/강화·적용/만료·차단/관통,독립 카운트/동시 기절/다음 상대·강제 교대,양쪽 회복 인계/부활 거절·회복 감소/봉인·입장 피해,새 실제 저장/동일 다음 입력·문맥 오염 거절·기존v18 호환을 묶는다. 사전 실제v18 체크포인트가 `/tmp/player-v18-before.bin`에 있으면 해당 사례도 확인하며 없으면 생략한다. 전체919기술/전체 suite/전체69전은 반복하지 않는다. 실제 창/native/X11·EXE/빌드는 계속 보류한다.
