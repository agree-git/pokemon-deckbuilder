# Pokemon Deckbuilder

포켓몬의 포획·육성과 카드 전투를 연결하는 2D 로그라이트 덱빌딩 게임.

## 개발 기준

- 목표 엔진: **Godot 4.7.2** (GDScript, Compatibility 렌더러).
- 언어: GDScript
- 첫 실행 대상: Windows PC
- 게임 기획: [docs/game-design.md](docs/game-design.md)
- Codex 작업 기준: [AGENTS.md](AGENTS.md)

## 현재 상태

**파이리·이상해씨의 공유 덱으로 뚜벅쵸와 싸우는 전투 한 판**을 플레이할 수 있다. 카드 사용, 에너지, 드로우·버리기·재섞기, 교체, 적 행동, 상성·보호막·화상·씨뿌리기, 기절·승패·재시작을 연결했다. 기본 화면은 슬레이 더 스파이어 배치를 참고한 1920×1080 UI이며 `F2`로 아트 랩과 전투를 오간다.

- 콘텐츠는 **관동 원종 #001~151**로 한정한다. 다른 지방·지역폼·메가진화는 전체 시스템 개발 뒤 추가한다.
- 관동 151종의 앞·뒤 도트 스프라이트 302장, 한글 이름과 현대 타입 정보를 로컬 에셋으로 포함한다.
- 18개 타입 바이옴의 배경·출현 목록을 준비했다. [바이옴 목록](docs/biomes.md)을 참고한다.
- 1세대 기술 165종을 재사용 가능한 공격·방어·회복·상태 연출에 연결했다. 원작의 개별 기술 애니메이션을 복제한 것은 아니며, 실제 피해·명중·상태 확률을 적용하지 않는 연출 프리뷰다.
- 화면·UI 기준은 **1920×1080**이며, 전체 화면을 저해상도로 렌더링하지 않는다. 도트 스타일은 그래픽에만 적용한다. 포켓몬 스프라이트는 최근접 필터와 정수 배율로 표시하고, 글자·카드·HUD는 화면 해상도에서 그린다.

## 전투 UI 틀

- 상단: 파티 체력, 골드, 포션 슬롯, 현재 지역, 전투 번호, 화면 전환.
- 중앙: 아군·적 스프라이트, 체력바, 적의 다음 행동 예고.
- 하단: 공유 에너지, 뽑을 더미, 부채꼴 손패 5장, 버린 더미와 턴 종료.
- 아군 교체 슬롯으로 전용 카드의 사용 가능 표시가 바뀐다. 카드 호버 시 위로 올라오고, 선택 시 해당 기술 연출을 재생한다.
- 체력·에너지·손패·더미·행동 예고는 실제 전투 상태를 표시한다. 연출 중 중복 입력을 막고, 기절하면 살아 있는 아군을 선택할 때까지 진행을 멈춘다. 종료 후 결과 화면에서 재시작할 수 있다.
- 전투 규칙은 Node에 의존하지 않는 `BattleState`에, 불변 카드·적 정의는 `BattleContent`에 분리했다. 화면은 데이터 조회와 행동 요청·연출만 담당한다.
- 현재 전투는 4타입과 소수 카드로 검증한다. 151종 전체의 전투 콘텐츠와 기술 165종의 게임 규칙을 모두 구현한 것은 아니다. [전투 규칙과 덱 구성](docs/battle-rules.md)을 참고한다.

## 실행과 검증

Godot 4.7.2로 `project.godot`을 열고 F5로 전투 UI를 실행한다. 로컬 에셋이 포함되어 있어 실행 중 네트워크와 API 키는 필요 없다.

```bash
# 이 클라우드 환경에서는 기본 Godot 4.6.3 대신 지정 엔진을 활성화한다.
source /workspace/.cloud-setup/pokemon-deckbuilder/env.sh
cd /workspace/pokemon-deckbuilder
godot --version
godot --headless --path . --editor --import
godot --headless --path . --script res://tests/test_battle.gd
godot --headless --path . --script res://tests/test_visuals.gd
godot --path .
```

카드를 눌러 사용하고, 왼쪽 아군 슬롯으로 교체한다. `Enter`는 턴 종료, `R`은 같은 시드로 재시작, `F11`은 전체화면, `F2`는 아트 랩 전환이다. 상단 `전투 기록`에서 피해·상태·기절 기록을 확인할 수 있다. 아트 랩을 오가도 현재 전투는 메모리에 유지되지만 앱을 종료하면 저장되지 않는다.

아트 랩에서는 바이옴·포켓몬·기술을 자유롭게 선택한다. `Space`는 재생, `←/→`는 바이옴 이동, `Esc`는 연출 초기화다. 아트 랩의 부가 상태는 확률 판정 없이 표시하는 연출 샘플이며 실제 전투 모델을 변경하지 않는다.

`test_battle.gd`는 카드 보존, 잘못된 행동의 무변경, 에너지·교체 비용, 드로우·재섞기, 상성·보호막·상태, 기절·승패·재시작과 30개 시드의 완결 전투를 검사한다. `test_visuals.gd`는 가져온 에셋과 실제 UI 조작을 통한 승리·패배·강제 교체·재시작·화면 재진입을 검사한다. 그래픽 렌더러로 검사할 때는 `--headless`를 빼면 된다.

현재 검증은 Linux의 Godot 4.7.2 헤드리스와 실제 Compatibility 렌더러에서 수행했다. Windows 실행과 내보내기는 아직 검증하지 않았다.

원본 스프라이트·데이터·폰트를 다시 내려받아 카탈로그를 재생성하려면 Python 3 표준 라이브러리만으로 `python3 tools/import_kanto_assets.py`를 실행한다. 고정된 업스트림 커밋과 파일별 SHA-256 기록을 사용한다. 출처·라이선스는 [ASSET_SOURCES.md](ASSET_SOURCES.md)에 기록했다.

## 다음 구현 목표

전투 한 판의 기반을 완성했으며, 다음 단계는 포획과 파티 성장이다.

1. 체력 조건과 몬스터볼 소비에 따른 포획.
2. 파티 합류·교체에 따른 전용 카드 추가·제거.
3. 전투 보상, 회복·부활, 경험치·진화.

지도·상점·원정 저장과 Windows 내보내기는 이후 단계다. 골드와 포션 슬롯은 배치만 준비했으며 아직 사용할 수 없다.

## 데이터와 구조

`scripts/battle/`에 콘텐츠 정의·포켓몬/카드 인스턴스·전투 상태·세션을 두고, `scripts/ui/`와 `scripts/vfx/`에 화면과 연출을 둔다. 시드 기본값은 2026이며 재시작하면 덱 순서가 동일하게 재현된다.

## 저장소 관리

소스, 씬, 기획 문서, 필요한 원본 에셋을 추적한다. Godot 캐시와 빌드 결과는 커밋하지 않는다. 실행과 테스트가 가능한 환경에서 Godot 버전을 확인하고 결과를 기록한다.
